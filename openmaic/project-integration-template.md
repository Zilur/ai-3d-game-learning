# 单课补充模板：理解 → AI初稿 → 人微调 → 主项目

日期：2026-09-15。适用于[项目主线](../curriculum/project-spine.md)。本文件是作者回填模板与一个填写示例，不是声明现有45课都已完成这次回填。沿用M/K和[0–2评分](../assessments/mastery.md)，不新增一套评分。

## 作者填写规则

每课在必要概念之后安排一次可理解的AI辅助体验，再接入主项目。不要只附一句“请AI帮我做”。本模板要回填到该课作者源并展开，不能要求学员自行拼接几个规则文档才能生成课堂。

M能力才要求实际选择、调整和验收。K认识课只需用途/取舍；选修不改主项目也可完成。OpenMAIC中的模拟不是实际Godot/Blender操作，真机配套未交付时明确分开记录。

每课填清：

1. **开始/结束画面或状态**：改前是什么、预计改后是什么；只能把确有的图片/运行结果标成真实证据。无素材先用标明的简图或状态对照，不伪造截图。
2. **AI学习指令**：让AI用一个反例或预测问题检查因果理解，先不揭答案。
3. **AI工作指令**：具体任务、允许改变的对象、保持不变的对象、预期交付物、版本与连接条件、检查和撤销办法。
4. **人工微调卡**：最多两三项；入口、初值来源、调整方向、观察对象、复位办法。项目自定义变量不要写成软件内置参数。
5. **不满意时的下一步**：方向不对补参考；结构不对定位职责；接近目标用手调；原因不明做对照。不给“多抽几次总会好”的建议。
6. **主项目接入**：落在哪个里程碑、资产/节点职责/状态，最后验证哪项旧功能没坏。
7. **短期风险与长期责任**：按工具版本记录能改善的错误；不预言能力上限。学员负责确认需求和认可证据，但可以让AI协助测量与批量调整。
8. **考核**：学员描述目标、做一个选择、提供一次操作/对照及解释；重点薄弱时才加诊断与迁移。

## AI指令的通用边界

若没有真实软件连接，AI只能提供已说明用途的脚本、建议或操作步骤，不能说已经修改文件或已经运行。执行前由学员或授权工具检查修改范围。密钥不进入课件；当前本地文件或截图先由学员按需提供，不让课堂假装已读整个电脑。

比较前记下实际软件版本、渲染器和相关初值。参考图需说明借鉴的是形状、颜色、光感还是构图；单张图片不包含可直接还原的全部三维信息，不要求无依据地复原精确光源数值。

## 填写示例：庭院基础光照（已有玩法不变）

**前置：** 基本主光/环境概念已学；庭院玩法已能走到收集和重开。真实软件环节在配套交付后进行。

**主项目增量：** 同一场景更接近温暖傍晚，仍能读出路径和拾取目标；不增加剧情或新玩法。

**开始/结束参考：** 同一游戏机位，保留当前截图；目标参考只借鉴暖主光与可读暗部。结束时也从该机位记录，不能用不同构图掩盖差异。

### 先用AI检查理解

```text
我已学过主光、环境光和材质自发光的用途。
请用“庭院变暖但暗角仍要看清”的场景，问我一个预测题。
先别给答案：只改变一个变量会有什么结果？
等我回答后指出理由中的缺口，再给最小验证办法。
不要展开GI算法，不要声称已观察到我没有提供的画面。
```

### 再让AI准备工作初稿

```text
任务：在我的现有小庭院里做一个可回退的基础光照初稿。
我会提供当前游戏机位截图、参考图、软件实际版本和渲染器信息。
仅借鉴参考图的暖主光、可读暗部和清楚主体，不复制角色或独特设计。

开始前先确认这些材料；缺少参数时列出待确认项，不猜成事实。
请先说明允许改动的光源/环境参数，记录现值，再做最小修改。
禁止改玩家移动、碰撞、拾取逻辑、UI计数、重开以及场景几何。
不要为了画面相似升级渲染器或堆多个未验证效果。

交付：一份初稿、实际改动清单、少数人工微调入口、撤销方法。
预期观察：主光偏暖，但路径和星星仍容易分辨。
不保证参数会精确匹配参考图；需要我从真实游戏视角验收。
没有编辑器/文件工具连接时，只给操作单或脚本并注明未执行。
```

### 人工微调卡

|项目|怎么调|看什么|何时停|
|---|---|---|---|
|主光能量|从实际初值向两边小幅改变，固定曝光和环境|主体亮面、暗角、星星与背景差异|继续加亮已损害可读性就撤回|
|主光方向|保持能量不变，一次转一个方向|脸/路面的明暗分布、阴影遮挡|不是只看静态截图，回到常用游戏机位|
|环境强度|前两项固定后再作对照|暗处是否可读，画面是否失去层次|达到本课目标就停止，不为“更专业”增加高级效果|

Godot的普通光能量可在Light3D派生光节点检查light_energy；物理光照单位、渲染模式会改变需要核对的设置。不是复制别人的数值就能得到同一画面。接口依据：[Light3D](https://docs.godotengine.org/en/stable/classes/class_light3d.html)。

单项视觉参数适合试着自己调整；批量改许多对象、设置结构或重复操作则可以再交给AI。拖动不是唯一方式，键盘输入数值、恢复按钮也可以。

### 当结果不满意

- 方向不对：指出“只要暖色，不要更暗”，给参考与当前图的具体差异，让AI只提局部改法。
- 已接近目标：先亲调一项，保留前后数值与同机位对照。
- 结果无法解释：恢复基线，让AI提出一个可验证假设；禁止继续全局随机修改。
- 找不到属性：核对实际版本/渲染器，查官方入口；不要把名字相似的参数盲目替换。

### 接入与考核

只将已选定的光照改动保留到P05。先走原来的收集路线，再检查最后一颗和重开；不必为光照课重考全部题库。

M证据：说明采用哪项参考特征、自己改了哪一项、观察到什么、为何取舍，以及一个相关旧功能仍正常。学员选对并验收即可，初稿由AI制作不扣分。只回答“AI说好了”不算证据。

K只问：烘焙或GI大致解决什么问题；不要求本课实现。迁移可换一个庭院角落，判断是否沿用同样调法，不照搬固定参数。

## 生成课堂的特别提醒

概念演示、AI过程演示和真实软件操作须有清楚标签。当前没有AI执行连接时，用可暂停的示例记录解释流程，不能伪装实时工具调用。教师应说明预期而非保证结果，保留学生先预测和实际观察的空间。

概念图用于说明“参考/目标→AI初稿→人工对照→局部反馈→验收”的关系；对照图须明确来源、条件和是否为示意。图稿/配套尚未制作时标为待补，不能勾选“已看到成品”。
