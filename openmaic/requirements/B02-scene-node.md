# OpenMAIC 生成输入｜B02 场景、节点与实例

生成中文互动课，英文术语第一次出现时配一句人话。学习者只做过B01A的Position/Rotation/Scale；没有碰撞算法、脚本和美术基础。产物是两个可复用灰盒模块，不是完整游戏。

## 开头显示学习深度

M必须掌握：①区分Node/Scene/Instance并选择正确职责；②整体移动与只改Visual的差别；③检查AI改动范围并恢复一个错误。
K理解即可：统一尺寸有助拼接，一句话用途足够。
停止线：不讲矩阵、碰撞算法、位掩码、PackedScene源码、深拷贝算法、角色控制、材质系统。

## 教学顺序

1. 显示父节点Module和三个孩子Visual、CollisionShape3D、Label。功能形状已配置，只认职责，下一课再讲碰撞。先操作再给名词。
2. 展示同一模块场景的两个实例A/B。学员先预测修改B位置会否移动A，再用滑块操作；同步显示场景树选中节点和参数。不要从位置独立推论材质全独立。
3. 切换“移动整体”和“仅移动Visual”，看到标牌/形状是否跟随。固定相机；支持Reset。显示形状只是教学可视化，不冒充Godot真实物理仿真。
4. 制造仅Visual偏移的故障。先收集学员假设，再给逐级提示；不一开始用答案讲解故障。迁移到不同名称/外形的模块，选择整体或外观节点。
5. 布置真实软件出口：Godot导入game/project.godot，F6运行lessons/b02/starter.tscn的练习副本；不要让学员F5进入完整星星工程。提供的reference与broken是实际文件，网页课堂不要谎称已修改了学员本机文件。

## 题目与评分

B02-P1：改B实例的位置会否移动A？操作后解释。
B02-R1：修复只移动了Visual造成的错位，不能删标牌/功能形状或挪相机掩盖。
B02-T1：只替换另一实例外观，保持根位置和功能节点。碰撞轮廓取舍留下一课。
B02-K1：统一尺寸有什么用？一句话即可，不追问实现。

M主要依据操作、解释、排错和迁移（90%反馈权重）；K仅用途识别（10%），不能抵消M失败。用0/1/2代表未完成/有提示/独立完成并解释。自动生成测验分数不能证明Godot实操通过。

## 质量要求

少量讲解、两个核心实验、一个可恢复故障即可。可重复考察同一关键能力，但不要每个术语单独出卷。AI同学最多提出一个常见误解，不进行无关辩论。参数控件要支持键盘、重置和窄屏；不只靠颜色区分对象。没有可运行的3D组件时用明确标注的简化2D树和位置模拟，不输出虚假运行成功。

最后给实操任务和停止条件：两个模块独立摆放，能选择整体/外观，能解释并恢复错位。以上完成即可继续B04，不能强制补完整软件教程。
