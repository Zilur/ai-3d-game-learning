# OpenMAIC 教学目标

请生成一个互动课堂，而不是文章朗读。

课堂必须优先采用：

1. 视觉演示
2. 参数对比
3. 场景判断题
4. 学习者主动操作
5. 错误案例
6. 最少必要文字

避免：

- 大段历史背景
- 过多数学推导
- 无关 API 罗列
- 软件菜单百科式介绍
- 为显得专业而堆术语

---

# 建议课堂结构

## Scene 1｜结果预览

先展示“学完以后能做成什么”。

不要先定义术语。

## Scene 2｜核心概念

使用最少文字介绍 3–8 个关键词。

每个词必须配视觉例子。

## Scene 3｜互动参数实验

如果本课存在可调参数，设计滑块 / 开关 / 对比视图。

例如：

- Roughness 0–1
- FOV 40–100
- Position X / Y / Z

要求：参数变化必须产生立即可见的结果。

## Scene 4｜错误案例

故意做一个错误版本，让学习者观察症状。

例如：

- Origin 偏移
- Collision 缺失
- Scale 异常
- Normal 反向

## Scene 5｜判断题 / Quiz

不要只考定义。

优先问：

> “现在遇到这个游戏问题，你应该先检查什么？”

## Scene 6｜真实软件任务

明确告诉学习者离开 OpenMAIC，打开 Godot / Blender 完成什么。

# 性能意识

回答：

- 这个功能是否有明显性能成本？
- 初级阶段应该观察什么指标？
- 现在需要优化吗，还是只需要知道风险？

不要为了优化而提前优化。

---

# 故意搞坏实验

设计一个 2–5 分钟的小实验：

1. 改坏一个关键参数
2. 观察症状
3. 判断问题属于哪个系统
4. 恢复正确值

Debug 能力必须从初级阶段就培养。

# 本课结束时应该会说的专业话

让学习者能够自然说出类似：

> “这个问题看起来不是 Mesh，而可能是 CollisionShape。”

或者：

> “我想让这个材质更粗糙，所以应该提高 Roughness，而不是单纯把颜色调暗。”

这是本课程“能与 AI 专业沟通”的核心验收之一。
