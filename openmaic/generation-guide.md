# OpenMAIC 使用流程

本仓库把 OpenMAIC 当作“互动课堂生成器”，而不是 Godot / Blender 的替代品。

## 推荐流程

1. 先阅读对应课程的 `openmaic-spec.md`，确认课程设计是否合理。
2. 使用 `openmaic/requirements/` 下对应的生成要求创建课堂。
3. 检查生成结果是否真的包含：
   - 视觉演示
   - 参数互动
   - 错误案例
   - 场景判断题
   - 真机练习出口
4. 如果课堂只是大量幻灯片和定义，不要继续使用，先修改 requirement 再生成。
5. 完成课堂后，进入 `curriculum/.../practice.md`，在 Godot / Blender 真机完成任务。
6. 把真实软件中遇到的问题记录下来，反过来改进下一版课程规格。

## 生成结果验收

### 好的课堂应该

- 先展示结果，再解释概念
- 让学习者亲自操作
- 参数改变有即时视觉反馈
- 用真实开发场景来出题
- 明确哪些高级知识现在不用学
- 最终把学习者送回真实 Godot / Blender

### 不合格课堂的典型症状

- 连续十几页概念定义
- 大量软件历史
- 过度数学推导
- 把所有功能都讲一遍
- Quiz 只问名词定义
- 为了炫技强行加入复杂 3D 互动
- 课程结束后学习者仍不知道下一步在真实软件里做什么

## 版本策略

不要一次生成整套 20+ 课。

推荐：

```text
课程规格 v1
→ OpenMAIC 生成
→ 实际上课
→ 记录问题
→ 修改课程模板
→ v2
→ 验证稳定后再扩展后续课程
```

第一阶段先把 B01 做到满意，再按同一模板继续 B02、B03。

## 未来自动化方向

在课程模板稳定后，可以增加脚本或工作流：

```text
课程规格 Markdown
        ↓
提取 OpenMAIC requirement
        ↓
提交课堂生成任务
        ↓
得到 Classroom URL
        ↓
将结果链接记录回课程索引
```

自动化不是第一优先级。

优先级始终是：**课程设计质量 > 生成速度。**
