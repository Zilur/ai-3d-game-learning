# OpenMAIC生成与验收 v2

本仓库保存课程规格；OpenMAIC负责生成课堂。生成不是确定性的编译，Markdown路径也不会自动成为平台可访问附件。

## 最小流程

复制 `requirements/B01-3d-space.md` 全文到课程要求。其他工作坊按模板整理后输入；附加材料需显式上传或提供平台可访问的内容，不只贴本地路径。

先检查大纲和必修边界，再生成一个样板。生成后依次操作全部滑块、输入框、Reset、问答和真机出口。留存“提示词版本+模型+平台版本+生成日期+课堂链接+验收结果”，不记录Key。

若有互动却没有预测/解释，要求补上；若只有静态PPT，标不通过；若物理/坐标演示错误，先修演示再试教，不用流畅旁白掩盖。

## 课堂验收清单

- 初始数值、单位、轴向、简化假设明确；对照只改一个变量。
- 可用键盘/数值输入，不只有鼠标拖动；XYZ有文字而不只靠颜色。
- 首次作答前隐藏答案；错误后分级提示，有迁移题。
- Reset能恢复完整状态；模型或素材加载失败有提示。
- 不把网页模拟说成Godot物理；PBR和性能不显示伪造效果或数字。
- 每个必修概念有题目ID、实际操作与可保存的证据。

## API边界（按2026-09-14读取的官方generate-flow）

`POST /api/generate-classroom` 使用 `requirement`，可选 `pdfContent`、`language` 和文档列出的能力开关。文档里的“interactive_spec”“questions”等自定义课程字段不能直接假设为API参数，应作为requirement正文或支持的材料传入。

先检查 `GET /api/health`；只开启服务确实支持的能力。LLM等供应商按服务端配置；不把Key写进课程仓库、浏览器HTML或聊天。模型/平台升级后重新核对接口。

提交成功只表示得到jobId，不等于课程生成成功。保存jobId后查询同一任务，不因短暂失败重复提交导致重复计费。只有最终成功的真实URL可登记为课堂成品。

本次没有调用生成接口、部署服务或设置自动任务。官方参考：[generate-flow.md](https://github.com/THU-MAIC/OpenMAIC/blob/main/skills/openmaic/references/generate-flow.md)。

## 效果验证

课堂“很好看”和学习“隔次仍能迁移”分开记录。B01首版已有学习者正向反馈，新版仍需按评分协议试教。不要从一个人的喜欢直接推断普适教学效果。
