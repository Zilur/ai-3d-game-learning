# 实际应用的验收：懂了、做过、会迁移分别记录

沿用[0–2评分](mastery.md)和[考核蓝图](exam-blueprint.md)，不加第三套分数。每课具体要求在[应用地图](../curriculum/application-map.md)及对应讲义第8节。

## 1. 必须掌握M如何留证

先回答本课在项目里解决什么问题；实际作一次选择、操作或对照；检查修改范围及一条相关旧功能；能用自己的话解释结果。AI可以提供代码、素材初稿、测试工具，菜单和API允许查。

普通M有一次有效操作/选择与解释即可记录当次表现。高频且返工风险大的M才加未知故障或隔次迁移；不要求每个词四项都重做。首次操作通过与隔次仍会分开，不在第一天伪称形成长期掌握。

没有真机配套、没有执行、或只有课堂模拟，状态为“模拟完成/真机待验证”，不能算工程应用通过。风格判断的真实产物可以是一页风格卡或实际作品的分析/变式，不要求每次都建模型。

## 2. 理解即可K怎样结束

一道轻量情境：它解决什么问题，什么时候查它。K不要求操作实现、详细排错或长报告。未选专题不计入当前阶段门槛。多人认识课只作用途/需求决定，不要求联网开发。

## 3. 最小证据单

```text
课号与实际场景：
我的目标、预测和不允许改动的部分：
我用AI做了什么 / 我自己选择或调整了什么：
实际结果：前后对照、一次演示或必要状态日志（择其足够者）
为什么认为满足目标 / 哪条相关旧功能仍正常：
提示：仅查资料 / 得到根因提示 / 照完整方案（如实记录）
恢复方式与仍未知的部分：
```

不强制上传个人录像、面孔、账户或本地路径；学习记录可保存在仓库之外。公开课程只保留模板与去个人化样例。

## 4. 一次综合任务覆盖多项概念

|任务站|可以共同检查|什么不能当通过|
|---|---|---|
|移动围栏，换外观|空间、节点职责、共享影响、回退|只看截图，功能部分已留在原处|
|进入星星区域|检测对象、事件、一次性状态、反馈|仅星星消失，实际重复计分|
|更新星星模型再重导|尺度、原点、材质与源文件职责|直接修缓存，下一次导入又丢掉|
|把庭院调成傍晚|参考描述、光与材质、参数比较、可读性|好看但路径/目标不可辨|
|走完收集并重开|输入、镜头、碰撞、计数、完成、恢复|删掉失败需求或测试后宣称修好|

只检查已经学过并已实现的内容；尚未有存档时不能把存档作为初级回归门槛。

## 5. 评分看证据，不看表面熟练

0：没证据、选错系统或未达目标。1：有针对性提示后完成，或结果虽对却解释不清。2：允许使用AI初稿和查菜单，学员能自己选择、观察、解释与恢复。依据当前受测能力标提示级别，不因AI写了基础工程就否定全部后续判断。

界面或设备故障先排除，再判断理解；自动测试通过是工程证据的一部分，不是学员掌握证据。文字写得漂亮但没有操作不能补M缺口。关键M失败不靠K得分抵消，具体阶段阈值仍采用mastery.md。

## 6. 主项目冻结线

初级始终是一块小场地、一个角色、简单平台和十颗星的收集循环。每课只改一项功能、视觉、手感或可靠性。新需求先放候选单，不为学高级名词而扩成战斗、背包、开放世界、多人项目。

中级一次选一个机关或简单敌人；动作/Shader/大场景先在副本，有证据再决定是否接入。同一项目可以美术升级、可靠性升级，未必增加系统数量。
