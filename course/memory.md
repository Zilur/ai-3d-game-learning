# 记在脑海里的概念与思维习惯

不是晨晚打卡，也不只是错题本。这里是需要逐渐形成熟悉感的词、关系和判断套路；没有疑问记录也可以回想。只练已经学过、当前路线用到的部分，K保持用途认识。
用法：遮住规则，先说自己的解释；找一个软件中的例子；换条件预测并验证。下次学习前或碰到同类问题时选一两项，不要求一次背全，也不把熟练说成永久不会忘。

API拼写、快捷键和菜单位置用时查；要内化的是它们解决什么问题、如何判断和验证。

## 关键术语与判断

<a id="kn01"></a>
### KN01｜坐标轴 Axis

**规则：** 世界轴与屏幕方向不是一回事；Godot向上是Y，Blender向上是Z。

**例子：** 转动相机后，世界 +X 会跟着相机改变吗？ 对照要点：世界轴不随相机旋转；屏幕上的投影方向会变。

**遮住后自问：** 转动相机后，世界 +X 会跟着相机改变吗？

**在哪些课遇到：** [A02](lessons/A02.md)、[C01](lessons/C01.md)。

<details><summary>学习边界</summary>

M：看轴标记选择方向；换观察视角不把屏幕右方当世界X；在Godot辨认Y向上、Blender辨认Z向上。K：坐标约定存在差异。停止：不背所有软件的前方、左右手系和转换公式。

</details>

<a id="kn02"></a>
### KN02｜变换 Transform

**规则：** Position改位置，Rotation改朝向，Scale改倍率；先确认改对象还是改内部网格。

**例子：** 宽2的网格Scale X=3，在无父级缩放时宽多少？ 对照要点：6个模型单位；Scale是倍数。

**遮住后自问：** 宽2的网格Scale X=3，在无父级缩放时宽多少？

**在哪些课遇到：** [A02](lessons/A02.md)、[B02](lessons/B02.md)、[C01](lessons/C01.md)。

<details><summary>学习边界</summary>

M：选对位置/旋转/缩放，知道Scale是比例而非绝对尺寸；B02通过一次对照区分移动对象与编辑网格。K：应用变换可能影响资产关系。停止：不手算矩阵，不把Apply All当通用修复。

</details>

<a id="kn03"></a>
### KN03｜局部与世界 Local / Global

**规则：** 位置相对谁、移动沿谁的方向要分开；父节点旋转后不能把局部量直接当世界量。

**例子：** 父节点只平移到(5,0,0)，子节点position=(2,0,0)，世界位置是多少？ 对照要点：(7,0,0)，条件是父级没有额外旋转/缩放。

**遮住后自问：** 父节点只平移到(5,0,0)，子节点position=(2,0,0)，世界位置是多少？

**在哪些课遇到：** [A07](lessons/A07.md)、[A08](lessons/A08.md)、[E04](lessons/E04.md)。

<details><summary>学习边界</summary>

M：看出位置相对谁、移动沿谁的方向；在父节点旋转后预测方向并查看世界位置验证。K：Basis/矩阵可实现转换，按需查。停止：不算任意旋转坐标，不背变换乘法；position通常是父空间不是自身前方。

</details>

<a id="kn04"></a>
### KN04｜原点与支点 Origin / Pivot

**规则：** 先找动作中应该不动的点；工具的临时Pivot不等于对象Origin。

**例子：** 门绕中心打转，优先改动画角度还是轴与网格的相对位置？ 对照要点：先查轴与网格的相对位置。

**遮住后自问：** 门绕中心打转，优先改动画角度还是轴与网格的相对位置？

**在哪些课遇到：** [A07](lessons/A07.md)、[A08](lessons/A08.md)、[C06](lessons/C06.md)。

<details><summary>学习边界</summary>

M：改变门轴与网格的相对关系，解释门和风车的区别；知道Blender工具Pivot不等于对象Origin。K：约束系统用途。停止：不学全部支点菜单或绑定系统。

</details>

<a id="kn05"></a>
### KN05｜场景、节点与实例 Scene / Node / Instance

**规则：** 节点各有职责，场景可复用为实例；换外观不应该顺便破坏控制、碰撞和状态。

**例子：** 同一颗星星要复用5次，复制5份脚本还是实例化场景更适合？ 对照要点：通常复用场景，位置各自设置，避免无目的复制行为脚本。

**遮住后自问：** 同一颗星星要复用5次，复制5份脚本还是实例化场景更适合？

**在哪些课遇到：** [A03](lessons/A03.md)、[B13](lessons/B13.md)、[C05](lessons/C05.md)。

<details><summary>学习边界</summary>

M：指出视觉、碰撞、控制和显示分别由谁负责；复用场景；替换外观不破坏功能。K：继承与组合是组织方式。停止：不背节点全集、设计模式或强制搭复杂框架。

</details>

<a id="kn06"></a>
### KN06｜外观、阻挡与检测 Mesh / Body / Area

**规则：** 外观负责看见，物理负责阻挡，区域负责检测重叠；三者分别验证。

**例子：** 隐藏墙Mesh，保留碰撞体，人能通过吗？ 对照要点：通常不能通过；Mesh可见性与碰撞启用独立。

**遮住后自问：** 隐藏墙Mesh，保留碰撞体，人能通过吗？

**在哪些课遇到：** [A04](lessons/A04.md)、[B06](lessons/B06.md)、[B13](lessons/B13.md)、[C01](lessons/C01.md)、[D06](lessons/D06.md)。

<details><summary>学习边界</summary>

M：用隐藏Mesh/禁用Shape对照验证；选择简单阻挡体和触发区域，检查其尺寸。K：凸/凹形状适用范围。停止：不实现碰撞检测算法，不为树叶默认做精确碰撞。

</details>

<a id="kn07"></a>
### KN07｜类别与检测目标 Layer / Mask

**规则：** Layer说自己属于什么类；Mask说检测者关注什么类。先讲清谁检测谁。

**例子：** 玩家在第2层；Area想检测它，至少该在Mask勾哪层？ 对照要点：Mask至少包含第2层；真正触发还需要有效形状、重叠、monitoring等条件。

**遮住后自问：** 玩家在第2层；Area想检测它，至少该在Mask勾哪层？

**在哪些课遇到：** [A04](lessons/A04.md)、[B06](lessons/B06.md)、[B13](lessons/B13.md)、[C06](lessons/C06.md)、[D06](lessons/D06.md)。

<details><summary>学习边界</summary>

M：按“谁检测谁”配置本课玩家/环境/拾取类别，排查一次检测失败。K：底层位掩码表示。停止：不考二进制位运算和复杂层级表，不把全层打开当修复。

</details>

<a id="kn08"></a>
### KN08｜输入、速度与时间 Input / Velocity / Delta

**规则：** 输入表达意图，速度是每单位时间的位移；不要把每帧位移误当速度。

**例子：** speed=4时写velocity.x=4*delta再move_and_slide，哪里可能错？可以查文档后解释。 对照要点：velocity表示每秒速度，重复乘delta会把它变成步位移；move_and_slide按物理步处理。可查官方文档。

**遮住后自问：** speed=4时写velocity.x=4*delta再move_and_slide，哪里可能错？可以查文档后解释。

**在哪些课遇到：** [A05](lessons/A05.md)。

<details><summary>学习边界</summary>

M：改输入映射和速度；区分每秒速度/每次位移；用给定测试对比同一秒结果，识别重复delta错误。K：渲染帧和物理步不同。停止：不推积分、不要求手写测试框架；API拼写可查。

</details>

<a id="kn09"></a>
### KN09｜跳跃、重力与落地 Jump / Gravity / Floor

**规则：** 起跳速度与重力共同影响跳高和滞空；落地是物理条件，不只看起来靠近地面。

**例子：** 重力变大而起跳速度不变，理想情况下跳得更高还是更低？ 对照要点：理想情况下更低、滞空更短；具体实测受步长和碰撞影响。

**遮住后自问：** 重力变大而起跳速度不变，理想情况下跳得更高还是更低？

**在哪些课遇到：** [A06](lessons/A06.md)。

<details><summary>学习边界</summary>

M：固定一个参数比较跳高/滞空；落地才能再次跳；区分斜坡与台阶问题。K：Floor Normal、贴地与容错跳跃用途。停止：不推弹道公式、不实现通用爬楼梯求解器。

</details>

<a id="kn10"></a>
### KN10｜镜头 Camera / FOV / Size

**规则：** 镜头改变观察，不改变物体尺寸或碰撞；本项目固定高角度，首先看清角色、主路和落点。

**例子：** 镜头变广角后，角色实际碰撞体会变小吗？ 对照要点：不会，FOV改变观察而不是物理尺寸。

**遮住后自问：** 镜头变广角后，角色实际碰撞体会变小吗？

**在哪些课遇到：** [A08](lessons/A08.md)、[C01](lessons/C01.md)。

<details><summary>学习边界</summary>

A08会在固定机位比较视野与移动方向；本项目不要求自由环绕、相机碰撞求解器或复杂切镜。

</details>

<a id="kn11"></a>
### KN11｜几何与表面 Geometry / Normal / Bevel

**规则：** 平滑着色改变光照外观，不自动改变轮廓；需要圆角轮廓才考虑几何。

**例子：** 平滑着色后立方体轮廓仍尖，为什么？ 对照要点：平滑着色不改变几何轮廓；需要圆角轮廓时考虑实际几何变化。

**遮住后自问：** 平滑着色后立方体轮廓仍尖，为什么？

**在哪些课遇到：** [B02](lessons/B02.md)、[D01](lessons/D01.md)。

<details><summary>学习边界</summary>

M：识别平滑着色不改轮廓、倒角会改几何；观察面朝向并验收AI资产。K：拓扑、重拓扑、法线贴图生成方式。停止：不把完整手工建模、法线数学、硬表面布线作为入门门槛。

</details>

<a id="kn12"></a>
### KN12｜材质 Material / Roughness / Metallic

**规则：** 固定灯光比较基础色、粗糙度和金属度；明亮或有高光不等于金属。

**例子：** 塑料很亮，应该一定把Metallic调到1吗？ 对照要点：非金属也可以有高光；先看粗糙度、灯光和环境。

**遮住后自问：** 塑料很亮，应该一定把Metallic调到1吗？

**在哪些课遇到：** [B04](lessons/B04.md)、[B13](lessons/B13.md)、[C02](lessons/C02.md)、[D02](lessons/D02.md)、[E03](lessons/E03.md)。

<details><summary>学习边界</summary>

M：固定灯光/相机，分别调基础色、粗糙度、金属度；用对照说明材质选择。K：PBR是材质工作流；Normal Map表现细节。停止：不讲BRDF/Fresnel推导，不要求画锈蚀贴图才能通过旧铁剑情境题。

</details>

<a id="kn13"></a>
### KN13｜发光、辉光与照明 Emission / Glow / Light

**规则：** 表面发亮、屏幕光晕、照亮邻物是不同路径，要分别验证。

**例子：** 星星亮了但地板没亮，一定是程序错吗？ 对照要点：不是必然错误。自发光、屏幕光晕、照亮旁物是不同路径；检查实际灯光或适用的间接照明条件。

**遮住后自问：** 星星亮了但地板没亮，一定是程序错吗？

**在哪些课遇到：** [B04](lessons/B04.md)、[B09](lessons/B09.md)、[D02](lessons/D02.md)、[E03](lessons/E03.md)。

<details><summary>学习边界</summary>

M：区别物体发亮、画面光晕、照亮旁物，分别验证而不混调。K：Glow/GI有渲染器和配置条件。停止：不实现Bloom或GI算法，不要求初级逐一配置所有GI方案。

</details>

<a id="kn14"></a>
### KN14｜贴图映射 UV / Texture

**规则：** UV决定贴图怎样落在表面；提高图片分辨率不能自动修正拉伸。

**例子：** 棋盘格被拉成长条，先提高贴图分辨率吗？ 对照要点：先检查UV/缩放；增加图片分辨率不会自动纠正映射比例。

**遮住后自问：** 棋盘格被拉成长条，先提高贴图分辨率吗？

**在哪些课遇到：** [B05](lessons/B05.md)、[C07](lessons/C07.md)。

<details><summary>学习边界</summary>

初级K：知道贴图映射失真应想到UV，能给出检索方向。中级M：用棋盘格检查一个简单资产、修一处拉伸、比较纹理密度。停止：不默认要求复杂角色展开、UDIM和生产级纹理管线。

</details>

<a id="kn15"></a>
### KN15｜资产往返 Source / Export / Import

**规则：** 改源文件或明确的外部资源；导入结果与玩法包装分开，重导入后检查旧功能。

**例子：** 重导入后手工改的材质丢失，首先应检查修改发生在哪里吗？ 对照要点：是，检查是否直接改了导入生成内容及材质编辑位置。

**遮住后自问：** 重导入后手工改的材质丢失，首先应检查修改发生在哪里吗？

**在哪些课遇到：** [B05](lessons/B05.md)、[C03](lessons/C03.md)、[D01](lessons/D01.md)。

<details><summary>学习边界</summary>

M：对静态资产检查实际尺寸、方向、原点；修改源文件、重导入并保留包装场景逻辑。K：格式限制、烘焙用途；角色不是静态资产工作流。停止：不手写glTF、不把绑定角色的变换处理塞进初级考核。

</details>

<a id="kn16"></a>
### KN16｜事件与状态 Event / State

**规则：** 先有事件与条件，再更新真实状态，最后更新反馈；表现不是状态的唯一来源。

**例子：** 把UI文字当作星星数量的唯一存储合理吗？同一物体重复触发应改变几次状态？ 对照要点：UI不是唯一状态源；一个一次性拾取物重复触发仍只改变一次状态。

**遮住后自问：** 把UI文字当作星星数量的唯一存储合理吗？同一物体重复触发应改变几次状态？

**在哪些课遇到：** [B06](lessons/B06.md)、[B08](lessons/B08.md)、[B13](lessons/B13.md)、[C04](lessons/C04.md)、[C06](lessons/C06.md)、[C10](lessons/C10.md)、[D06](lessons/D06.md)、[D07](lessons/D07.md)。

<details><summary>学习边界</summary>

M：说明触发者、过滤条件、状态拥有者与UI更新顺序；检查正确/错误对象、重复拾取、最后一颗、重开。K：延迟释放和生命周期用途。停止：不写通用事件总线、不背所有回调。

</details>

<a id="kn17"></a>
### KN17｜共享资源 Shared Resource

**规则：** 两个独立节点仍可能引用同一资源；只复制确需变化的部分，不盲目复制所有大纹理。

**例子：** 只改一个球的材质，另一个也变了，优先怀疑什么？怎样只改目标球？ 对照要点：优先检查共享材质资源；使用Make Unique或等效分离，再确认另一球不变。

**遮住后自问：** 只改一个球的材质，另一个也变了，优先怀疑什么？怎样只改目标球？

**在哪些课遇到：** [B04](lessons/B04.md)、[C02](lessons/C02.md)、[C05](lessons/C05.md)、[C10](lessons/C10.md)、[D03](lessons/D03.md)。

<details><summary>学习边界</summary>

初级M：两个物体共用材质，能预测“改一处影响谁”，用Make Unique或等效方式只改目标。中级M：决定哪些数据共享、哪些实例独立。K：深/浅复制与缓存机制。停止：不考递归复制和资源管理器内部实现。

</details>

<a id="kn18"></a>
### KN18｜反馈与可读性 Feedback / HUD

**规则：** 结果要清楚可辨；静音、颜色难辨或低运动下仍应知道发生了什么。

**例子：** 静音后完全不知道是否拾取，缺什么？ 对照要点：需要独立视觉反馈，如计数、形状或短文字。

**遮住后自问：** 静音后完全不知道是否拾取，缺什么？

**在哪些课遇到：** [B07](lessons/B07.md)、[B08](lessons/B08.md)、[B13](lessons/B13.md)、[C01](lessons/C01.md)、[C02](lessons/C02.md)、[D06](lessons/D06.md)。

<details><summary>学习边界</summary>

M：成功/失败可辨；静音或颜色不易区分时仍能理解结果；控制效果强度。K：粒子、音频空间化的可选手段。停止：不要求精通全部特效节点，也不按“越炫越高分”评分。

</details>

<a id="kn19"></a>
### KN19｜帧时间与测量 FPS / Frame time

**规则：** 平均帧率掩盖不了慢帧；比较时固定设备、设置、路线和版本。

**例子：** 平均60FPS就保证每帧都在约16.7ms内吗？ 对照要点：平均值不保证每帧都符合预算。

**遮住后自问：** 平均60FPS就保证每帧都在约16.7ms内吗？

**在哪些课遇到：** [B11](lessons/B11.md)、[C01](lessons/C01.md)、[C09](lessons/C09.md)、[E02](lessons/E02.md)。

<details><summary>学习边界</summary>

M：记录设备/版本/分辨率/路线；区分平均FPS与慢帧；开关一个效果验证变化。K：CPU/GPU、Draw Call、显存指标的用途。停止：初级不抓GPU帧，不强制计算分位数，不把1000/FPS当GPU耗时。

</details>

<a id="kn20"></a>
### KN20｜AI协作与排错 Debug / Regression

**规则：** 说清目标和保持项；先复现，再局部修改、验旧功能，必要时回退。

**例子：** AI同时改了多个系统才不报错，你能直接认定问题修好吗？至少还看什么？ 对照要点：不能；检查修改范围、是否保留需求、原错误和相关功能是否复测。

**遮住后自问：** AI同时改了多个系统才不报错，你能直接认定问题修好吗？至少还看什么？

**在哪些课遇到：** [A03](lessons/A03.md)、[B12](lessons/B12.md)、[B13](lessons/B13.md)、[C12](lessons/C12.md)、[E07](lessons/E07.md)。

<details><summary>学习边界</summary>

M：明确需求和不能改的部分；看修改范围；读一条输入→条件→状态→反馈因果链；复现、改一处、回归、回退；不公开密钥。K：分支和自动化测试工具用途。停止：不背Git内部命令或把所有辅助代码逐行讲完。

</details>

<a id="kn21"></a>
### KN21｜角色、骨架与动画 Rig / Skin / Animation

**规则：** 外观、形变、移动和动画条件分别检查；先验一段兼容动作，再扩大接入。

**例子：** 角色站着却播放跑步，先查动画状态条件还是立刻重做蒙皮？ 对照要点：先看输入/运动状态和动画切换条件，不能仅凭播放错动作就认定蒙皮坏了。

**遮住后自问：** 角色站着却播放跑步，先查动画状态条件还是立刻重做蒙皮？

**在哪些课遇到：** [C03](lessons/C03.md)、[C04](lessons/C04.md)、[D05](lessons/D05.md)、[D06](lessons/D06.md)、[D07](lessons/D07.md)。

<details><summary>学习边界</summary>

中级M：接入现成角色并保持碰撞；检查动画名称/状态条件；测试待机、移动、跳落地过渡。K：骨骼/蒙皮用途、Root Motion与权重修正方向。停止：不强制从零绑定、刷权重、实现蒙皮或复杂IK。

</details>

<a id="kn22"></a>
### KN22｜模块化 Modular / Snap

**规则：** 统一尺寸、原点和拼接规则，再批量组合；吸附不自动修复不一致的模块。

**例子：** 每片墙长度不同却要求无缝Grid拼接，先检查什么？ 对照要点：先统一尺寸、原点和网格约定。

**遮住后自问：** 每片墙长度不同却要求无缝Grid拼接，先检查什么？

**在哪些课遇到：** [C01](lessons/C01.md)、[C07](lessons/C07.md)、[D03](lessons/D03.md)。

<details><summary>学习边界</summary>

初级K：知道统一尺寸和原点利于拼装。中级M：用少量模块按同一网格拼接，查缝隙和碰撞。K：Trim Sheet、贴花用途。停止：不要求完整环境资产生产线。

</details>

<a id="kn23"></a>
### KN23｜导航 Navigation

**规则：** 路径规划认为可走，不代表当前碰撞体与控制器实际能走过。

**例子：** 有路径线却过不去，导航一定坏了吗？ 对照要点：不一定；路径结果与实际碰撞/控制行为要分别验证。

**遮住后自问：** 有路径线却过不去，导航一定坏了吗？

**在哪些课遇到：** [E01](lessons/E01.md)。

<details><summary>学习边界</summary>

选择导航单元后M：用现成导航组件测试巡逻/追踪，区别路径线与实际可达性，检查门的变化。K：寻路算法、避障算法。停止：不实现A*；选择纯机关项目可跳过导航实操。

</details>

<a id="kn24"></a>
### KN24｜存档与恢复 Save / Version

**规则：** 先明确保存哪些状态；缺失、损坏和旧版本要有可解释的处理，不覆盖唯一有效数据。

**例子：** 旧存档没有新字段，应该直接崩溃吗？ 对照要点：应设计默认值、版本处理或明确恢复，不直接让用户崩溃。

**遮住后自问：** 旧存档没有新字段，应该直接崩溃吗？

**在哪些课遇到：** [C11](lessons/C11.md)、[C12](lessons/C12.md)、[D07](lessons/D07.md)。

<details><summary>学习边界</summary>

M：确定保存哪些状态；检查无文件/旧数据/损坏数据的恢复；验收音量和输入设置。K：原子写入、迁移机制用途。停止：不要求数据库、云存档、复杂序列化框架。

</details>

<a id="kn25"></a>
### KN25｜灯光与环境 Lighting / Environment

**规则：** 固定材质和机位，一次只改主光或环境；照明方案受动态对象与设备条件约束。

**例子：** 角色很暗，应该同时改所有材质、灯光和曝光吗？你先固定哪些条件？ 对照要点：不要同时改全部。固定机位、材质、渲染器，选择主光或环境一项做对照。

**遮住后自问：** 角色很暗，应该同时改所有材质、灯光和曝光吗？你先固定哪些条件？

**在哪些课遇到：** [B09](lessons/B09.md)、[C02](lessons/C02.md)、[C08](lessons/C08.md)、[D02](lessons/D02.md)、[D07](lessons/D07.md)。

<details><summary>学习边界</summary>

初级M：在固定渲染器下调主光/环境强度，比较阴影和主体可辨性。中级M：按动态物体和目标设备选择一种可行方案并验收。K：曝光、色调映射、实时/烘焙与GI类别用途。停止：不推光传输，不把“掌握光照”理解成实现渲染器。

</details>

<a id="kn26"></a>
### KN26｜目标平台与来源 Platform / License

**规则：** 只对测过的条件作承诺；免费不等于可再分发，资源来源与许可要能找回。

**例子：** 资源写着free就可以把它的源文件公开放进仓库吗？你要确认什么？ 对照要点：不能仅据free判断。查看具体允许用途与再分发条件，不明就不要公开源文件；不要求背法律条文。

**遮住后自问：** 资源写着free就可以把它的源文件公开放进仓库吗？你要确认什么？

**在哪些课遇到：** [A03](lessons/A03.md)、[B02](lessons/B02.md)、[B11](lessons/B11.md)、[C02](lessons/C02.md)、[C03](lessons/C03.md)、[C12](lessons/C12.md)、[D03](lessons/D03.md)、[D05](lessons/D05.md)、[D07](lessons/D07.md)、[E07](lessons/E07.md)。

<details><summary>学习边界</summary>

M：开工先写目标平台/设备范围；导入素材先查允许用途和再分发条件，不明就不公开源资产；在目标条件复验。K：授权类型、硬件术语。停止：不考法律条文、不要求背显卡规格；课程不代替具体授权审查。

</details>

<a id="kn27"></a>
### KN27｜Shader视觉效果

**规则：** Shader改变画面不自动改变物理；一次只做一个可关闭、值得保留的效果。

**例子：** 草在Shader中摇摆，物理形状必然同步吗？ 对照要点：不必然同步，Shader视觉变化不自动改变物理形状。

**遮住后自问：** 草在Shader中摇摆，物理形状必然同步吗？

**在哪些课遇到：** [E03](lessons/E03.md)。

<details><summary>学习边界</summary>

仅选择E03后M：让AI生成一个小效果并暴露参数；检查边界值、视觉/碰撞不一致和成本。K：管线内部细节。停止：不要求从零写渲染引擎；初中级不考Shader语法。

</details>

<a id="kn28"></a>
### KN28｜复杂旋转与插值 Rotation / Interpolation

**规则：** 旋转表示与路径会影响结果；先画期望轨迹，再测跨边界与父空间变化。

**例子：** 为什么方向接近的两个朝向也可能沿很长轨迹插值？ 对照要点：角度表示和插值方式可能走到长轨迹；用179°到-179°例子观察。

**遮住后自问：** 为什么方向接近的两个朝向也可能沿很长轨迹插值？

**在哪些课遇到：** [E04](lessons/E04.md)。

<details><summary>学习边界</summary>

仅选择E04后M：定义目标轨迹，测试跨±180°与父节点旋转，验证插值方向。K：Quaternion/Basis用途。停止：不背四元数公式；未遇到复杂旋转不必学此单元。

</details>

<a id="kn29"></a>
### KN29｜批量绘制 MultiMesh / Draw call

**规则：** 场景实例不等于一次绘制；批量减少提交，也可能降低剔除粒度。

**例子：** 1000个实例就一定只有1个Draw Call吗？ 对照要点：不保证；场景实例和GPU绘制批次不是同一概念。

**遮住后自问：** 1000个实例就一定只有1个Draw Call吗？

**在哪些课遇到：** [C09](lessons/C09.md)、[E05](lessons/E05.md)。

<details><summary>学习边界</summary>

初中级K：知道大量重复物体有批量绘制工具，需要先证实瓶颈。选择E05后M：比较普通实例与分区批量方案，验收视角变化和交互约束。停止：不考GPU实例化底层实现。

</details>

<a id="kn30"></a>
### KN30｜细节与驻留 LOD / Culling / Streaming

**规则：** 远处少画细节、不可见不画、释放资源是不同事；分别测量。

**例子：** 远景降面数后内存仍高，是否还应检查资源驻留？ 对照要点：应考虑资源是否仍加载；减少可见几何不等于释放资源。

**遮住后自问：** 远景降面数后内存仍高，是否还应检查资源驻留？

**在哪些课遇到：** [C09](lessons/C09.md)、[E05](lessons/E05.md)。

<details><summary>学习边界</summary>

初级K仅记“远处可减少细节”；中级再认识剔除和驻留。选择E05后M：按问题选择LOD、剔除或加载策略，检查跳变、内存和慢帧。停止：初中级不要求写流送系统。

</details>

<a id="kn31"></a>
### KN31｜联网裁定 Authority / Latency

**规则：** 联网要协调谁裁定唯一状态，处理延迟和重发。只作选修用途认识。

**例子：** 两人同时报告拾取，谁决定唯一结果？ 对照要点：需要预先明确具有最终裁定权的一方，通常采用服务器权威的方案。

**遮住后自问：** 两人同时报告拾取，谁决定唯一结果？

**在哪些课遇到：** [E06](lessons/E06.md)。

<details><summary>学习边界</summary>

主线不考。选择E06后先K：谁裁定状态、延迟/重连会带来什么问题。只有明确选择网络实作项目才另列M合同；不能沿用单机结业卷强加网络任务。

</details>

<a id="kn32"></a>
### KN32｜性能基线与回归 Baseline / Bottleneck

**规则：** 先定位真实问题，用可重复对照衡量收益，再检查功能和画面是否退化。

**例子：** 降分辨率后明显变快，能直接证明是三角形太多吗？ 对照要点：不能直接证明，分辨率变化影响多类屏幕工作负载；进一步对照。

**遮住后自问：** 降分辨率后明显变快，能直接证明是三角形太多吗？

**在哪些课遇到：** [E02](lessons/E02.md)、[E07](lessons/E07.md)。

<details><summary>学习边界</summary>

高级M：提出瓶颈假设，用固定条件和基线验证修复，检查慢帧和功能/视觉回归。K：外部分析工具原理。停止：不规定通用面数阈值、不按掌握工具数量评分。

</details>

<a id="art01"></a>
### ART01｜Style brief 风格说明；保留/排除项

**规则：** 用五维描述让AI知道目标和禁区。
**例子：** 做小小美术导演：从已有参考选一项借鉴、一项不借鉴，并指给爸爸看。
**遮住后自问：** 另一张图也很漂亮，为什么不一定适合我们的同一个世界？
**在哪些课遇到：** [A01](lessons/A01.md)、[C02](lessons/C02.md)、[D04](lessons/D04.md)。
**边界：** 不背艺术流派史。

<a id="art02"></a>
### ART02｜Silhouette 剪影；Proportion 比例；Negative space 空隙形成的形状

**规则：** 在缩略图辨认轮廓，修一处比例或间隙。
**例子：** 做小小美术导演：从已有参考选一项借鉴、一项不借鉴，并指给爸爸看。
**遮住后自问：** 另一张图也很漂亮，为什么不一定适合我们的同一个世界？
**在哪些课遇到：** [A01](lessons/A01.md)、[B01](lessons/B01.md)、[C02](lessons/C02.md)、[D01](lessons/D01.md)。
**边界：** 不要求解剖学或雕刻工艺。

<a id="art03"></a>
### ART03｜Primary/Secondary/Tertiary 主形/中形/小细节；Detail density 细节密度

**规则：** 先大后小，按游戏镜头决定细节预算。
**例子：** 做造型侦探：缩小两座小屋的画面，先比较大形，再决定一处比例变化。
**遮住后自问：** 多加十个装饰会让形状更好认，还是可能更难认？用玩家距离说明。
**在哪些课遇到：** [B01](lessons/B01.md)、[C02](lessons/C02.md)、[D01](lessons/D01.md)、[D04](lessons/D04.md)。
**边界：** 不把某个固定比例当万能配方。

<a id="art04"></a>
### ART04｜Hue/Saturation/Value 色相/饱和/明暗；Palette 色盘

**规则：** 固定其他条件调关系，选择有理由的色盘。
**例子：** 做颜色导演：固定机位和光照，只改一类颜色关系，让爸爸找第一眼焦点。
**遮住后自问：** 只让所有东西更鲜艳，会不会让主路更清楚？怎样对照？
**在哪些课遇到：** [B03](lessons/B03.md)、[D02](lessons/D02.md)、[D04](lessons/D04.md)。
**边界：** 不学颜色转换公式；软件数值定义用时查。

<a id="art05"></a>
### ART05｜Focal point 焦点；Hierarchy 主次；Composition 构图

**规则：** 能说第一眼看到什么，给一个明确调整。
**例子：** 做颜色导演：固定机位和光照，只改一类颜色关系，让爸爸找第一眼焦点。
**遮住后自问：** 只让所有东西更鲜艳，会不会让主路更清楚？怎样对照？
**在哪些课遇到：** [B03](lessons/B03.md)、[B10](lessons/B10.md)。
**边界：** 不强制黄金比例等规则。

<a id="art06"></a>
### ART06｜Moodboard 参考板；Thumbnail 缩略图；Study 局部研习

**规则：** 带问题看一图，提原则后换主题。
**例子：** 做美术提案人：把一条参考规则用在自己的庭院，说明为什么保留某些空白。
**遮住后自问：** 参考作品中的细节全部搬过来，会不会破坏我们的小地图？
**在哪些课遇到：** [B10](lessons/B10.md)、[D04](lessons/D04.md)。
**边界：** 参考板不是素材授权。

<a id="art07"></a>
### ART07｜Look development 质感与外观标准；Painterly 手绘观感；Toon/Cel 卡通分块

**规则：** 建立同风格下不同材质的对照标准。
**例子：** 做风格协调员：固定光照，先统一一件资产的颜色，再单独比较粗糙度。
**遮住后自问：** 每件资产单看都漂亮，放到一起为什么仍然可能不协调？
**在哪些课遇到：** [D02](lessons/D02.md)。
**边界：** 具体描边/手绘/烘焙技术按需学。

<a id="art08"></a>
### ART08｜Base mesh 基底；Variant 变体；Kitbash 组合改造；Asset library 资源库

**规则：** 选可靠基底、改造、记录、复用并控制影响范围。
**例子：** 做资产图书管理员：为一件资产留下来源、用途、版本和固定机位预览。
**遮住后自问：** 下次发现错误，怎样找到源文件，而不是继续修改导出的成品？
**在哪些课遇到：** [D03](lessons/D03.md)、[D04](lessons/D04.md)。
**边界：** 不要求制作资产管理平台。

<a id="art09"></a>
### ART09｜Anticipation 起势；Contact 接触；Recovery 恢复；Follow-through 跟随动作

**规则：** 选择专题后能读节奏、对齐动作与事件。
**例子：** 做训练角裁判：先验证一次有效命中和恢复移动，再选择一层反馈。
**遮住后自问：** 震屏很强但重复扣分，应该先调整效果还是修正命中规则？
**在哪些课遇到：** [D06](lessons/D06.md)。
**边界：** 专业武打编排、动捕清理不是必修。

<a id="thinking"></a>
## 经常用到的思维模式

这些不是要背的口号；在真实操作中主动用一次，比复述口号更重要。

<a id="th01"></a>
### TH01｜把愿望说成目标

**规则：** 我想得到什么、哪些保持、怎样看出结果？
**例子：** 不要只说更漂亮；指出保持圆润屋顶，只减少背景高对比细节。
**遮住后自问：** 这次我到底允许AI改什么？
**在哪些课遇到：** [A01](lessons/A01.md)、[B10](lessons/B10.md)、[B13](lessons/B13.md)。

<a id="th02"></a>
### TH02｜先问选中了谁、相对谁

**规则：** 对象、职责和坐标空间确认后再动手。
**例子：** 只调角色外观时，不把整个控制器和碰撞一起缩小。
**遮住后自问：** 我改的量属于哪个对象、以谁为参照？
**在哪些课遇到：** [A02](lessons/A02.md)、[A03](lessons/A03.md)、[A07](lessons/A07.md)。

<a id="th03"></a>
### TH03｜先预测，一次只改一个条件

**规则：** 有预测再做对照，才能知道结果支持哪种解释。
**例子：** 材质、机位不变，只改粗糙度；不同时换灯光。
**遮住后自问：** 什么必须固定，才能比较这次变化？
**在哪些课遇到：** [A04](lessons/A04.md)、[B04](lessons/B04.md)、[C08](lessons/C08.md)。

<a id="th04"></a>
### TH04｜沿着原因走到结果

**规则：** 谁触发、什么条件、谁拥有状态、谁显示反馈？
**例子：** 重复拾取时先看一次性状态，不只看星星是否隐藏。
**遮住后自问：** 现在看到的是效果，还是规则真的执行了？
**在哪些课遇到：** [B06](lessons/B06.md)、[B08](lessons/B08.md)、[C10](lessons/C10.md)、[C11](lessons/C11.md)。

<a id="th05"></a>
### TH05｜留基线、改局部、验旧功能

**规则：** 保留可恢复版本，接受修改前检查原要求仍成立。
**例子：** 换模型后重走旧路线，测试碰撞、收集和重开。
**遮住后自问：** 新功能好了，原来能做的事有没有变坏？
**在哪些课遇到：** [A03](lessons/A03.md)、[B05](lessons/B05.md)、[B12](lessons/B12.md)、[D07](lessons/D07.md)。

<a id="th06"></a>
### TH06｜区分猜测、执行和证据

**规则：** AI说完成不等于实际跑过；不确定的写待验证，不补造日志。
**例子：** 平均帧率变高但没有同设备同路线对照，不能归功于某个优化。
**遮住后自问：** 哪些是我实际观察到的，哪些还只是解释？
**在哪些课遇到：** [B11](lessons/B11.md)、[B12](lessons/B12.md)、[C09](lessons/C09.md)、[E02](lessons/E02.md)。
