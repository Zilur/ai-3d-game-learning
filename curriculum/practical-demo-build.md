# 实战主项目：按真实流程完成“星光小庭院”精致 Demo

本项目已经进入真实工程阶段。目标不是复刻商业游戏，而是用自己的关卡、合法资产和二开流程，实践当前参考中提炼出的视觉语言：**固定/有限高角度、干净、自然、温暖、颜色受控、材质柔和、丰富但有留白。**

详细区分“概念实验室”和“正式项目”的规则见 [概念实验室与正式项目](lab-production-workflow.md)。

## 最终竖切片

工作名：**星光小庭院**。

基础版最终应有：

- 固定/有限高角度镜头。
- 角色走、跑、跳。
- 庭院 → 林路 → 观景台的短探索路线。
- 十颗星星收集、完成和重开。
- 一个明确地标和几个小型平台/高差。
- 统一后的树、石、建筑、道路和生活道具。
- 干净的构图和受控植被密度。
- 柔和光照、少量氛围/VFX。
- 可选的一两件 Hero 资产。

增强版再加入：

- 正式角色与待机/走/跑/跳动作。
- 一段现成攻击动作。
- 一个可绕过的训练木桩。
- 命中、目标反应、粒子/Trail/Sound/Hit Stop 和可选镜头冲击。

## 真正的工作顺序

### 0. 先锁方向，不做精修

确定范围、镜头、目标平台、视觉参考和风格卡；定义“不做什么”。

**AI任务：** 帮忙整理约束、列风险、把参考提炼成 5–8 条视觉规则。
**人验收：** 规则是否真的代表想做的游戏；不能让 AI 用某个商业游戏的具体资产/关卡替代规则。

### 1. 灰盒：先结构、尺度和路线

只用 Box/Capsule/Plane 搭：起点、主路、坡、平台、小屋占位、地标占位、终点。

这里先解决：

- 角色跑多远才觉得地图“有一点空间”。
- 固定镜头能否看清角色和落点。
- 门/路/平台比例是否舒服。
- 主路线和支路是否一眼可读。

**Gate：** 不靠美术也能看懂路线；走跑跳不卡；镜头不要求玩家持续转动。

### 2. 核心逻辑：代理资产上完成闭环

完成走跑跳、碰撞/Trigger、十星、UI、完成、重开、必要状态与事件。

**AI任务：** 写局部实现、补测试、列修改范围。
**人验收：** 玩法状态是否正确、重复进入是否出错、重开是否干净。

**Gate：** 一轮从开始到完成可以重复跑通。

### 3. 灰盒回归：先修结构问题

在加入正式素材前完整试玩几轮。修：路线过长/过短、视线遮挡、跳跃尺度、碰撞、镜头边界、目标可读性。

这一步禁止用“换漂亮模型”解决结构问题。

### 4. 美术竖切片：只精修一个小区域

挑一个玩家会经过 10–20 秒的转角，先做我们真正想要的品质：

- 一栋小屋/建筑模块。
- 一棵主树 + 一组小植被。
- 一块石头/生活道具。
- 一段道路与地面过渡。
- 基础灯光与色盘。

候选素材在这里第一次正式进入。只换少量对象，并在 Blender 做二开。

**Gate：** 这个区域在真实玩家机位能达到我们自己认可的“至少值得继续扩”的水平；如果做不到，先换资产策略或风格规则，不批量生产。

### 5. 锁资产母体与导入合同

确认主环境包和少量补充包。对每类资产记录：

来源/许可、单位、前向、Origin、材质槽、纹理、碰撞策略、LOD/复杂度（需要时）、Blender 主文件、Godot 导入结果。

购买标准见 [素材包采购指南](../art/asset-pack-buying-guide.md)。

### 6. Blender 二开：把素材变成我们的资产

统一顺序：

**用途与游戏机位 → 大形/比例 → 模块替换/Kitbash → 配色 → 材质 → 有限细修 → 导出。**

优先改玩家能看见、能感知的部分；不为“原创”重做全部模型。

AI可以给操作顺序、批量重命名和材质槽整理；人决定比例、模块、颜色、材质是否成立。

### 7. 分批替换灰盒

一次替换一个家族：

1. 树/植被。
2. 建筑模块。
3. 岩石/道路。
4. 生活道具。
5. Hero 资产。

每批固定同一机位前后对比，并回归：路线、碰撞、星星、镜头、性能。

**禁止：** 一次把整张地图全替换后再找问题。

### 8. 风格统一

当不同来源资产进入同一场景后，按四层处理：

- 比例/轮廓。
- 色盘与明暗关系。
- Roughness/Metallic/Emission 等材质语言。
- 细节密度。

先做一个样板转角，通过后再批量扩展。

### 9. Set Dressing：做生活感，也做减法

补花、草、围栏、桶、篮子、路牌、木堆等，但以“簇”为单位。

每加一批都做：

- 缩小图检查。
- 第一眼焦点检查。
- 主路净空检查。
- 删掉 30–50% 后是否反而更好。

“减少东西”是这一阶段的正常工作。

### 10. 灯光、后处理、VFX、声音

结构和资产稳定后再做最终表现：主光、环境光、Fog/Glow/色彩调整、粒子、风、落叶、星星反馈、声音。

固定视角允许短促 Camera impulse、FOV/Size Pulse，但普通移动不持续晃镜头；低运动模式下仍需靠非镜头反馈读懂事件。

### 11. 角色与动作

先在小测试里完成角色尺寸、骨架、重定向、待机/走/跑/跳，再接正式项目。

攻击分三层：

**动画播放 → 命中规则 → 视觉/声音反馈。**

三个职责分别验收，不能因为动画挥到了就默认命中正确。

### 12. 性能与交付

最后在目标平台和分辨率检查：慢帧、阴影/VFX成本、输入、窗口、重开、导出。一次只优化一个真实瓶颈。

## 每个阶段怎么指挥 AI

统一模板：

```text
当前阶段 / Gate：
现在已经通过的东西：
本次唯一问题：
允许改：
禁止改：
请先给 1–3 个候选，不要直接重构。
选定后只实现一个可撤销版本。
完成后给：修改范围、验证证据、仍未验证、回退方法。
```

如果 AI 产出跨过当前 Gate，例如在灰盒阶段开始加复杂 Shader，直接拒绝并拉回当前阶段。

## 细节打磨时的优先级

当功能已经成立，按下面顺序找最大问题，而不是随机调参数：

1. 构图和主次。
2. 比例和轮廓。
3. 配色与明暗。
4. 材质语言。
5. 植被/道具密度。
6. 灯光。
7. VFX/声音。
8. 性能与兼容。

前一层明显有问题时，不用后一层特效遮盖。

## 当前真实状态

仓库已有可运行的固定高角度第一版、走跑跳、十星闭环、视觉 A/B 实验室，以及概念实验材料。它仍是**工程骨架/视觉基线**，不是已经达到参考商业作品的美术品质。

下一步真实工作是：完善概念实验室 → 做第一处正式美术竖切片 → 用免费/候选资产进行第一次 Blender 二开和 Godot 固定机位 A/B。
