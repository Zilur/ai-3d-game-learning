# 实战 AI 指挥手册：人做导演，AI做可验证的执行层

目标不是写一条“神提示词”，而是让 AI 在真实 Godot/Blender 项目里持续交付可检查的小改动。

## 1. 长期职责

### 人必须负责

- 最终想做成什么感觉。
- 当前只解决哪个问题。
- 哪些旧功能不能被破坏。
- 选择哪个资产/方案/参数。
- 判断画面是否干净、舒服、统一。
- 决定 AI 产出是采纳、修改还是回退。
- 认可什么证据算完成。

### AI适合负责

- 拆解目标并提出少量候选。
- 写局部脚本、节点/资源初稿和重复设置。
- 给 Blender 二开的具体操作顺序。
- 批量改名、改材质槽、生成变体和检查清单。
- 根据运行日志定位候选原因。
- 执行自动测试、记录修改范围和未验证项。

## 2. 每次开工都给 AI 五样东西

```text
当前目标：
当前工程/软件版本：
现在已经成立的东西：
这次允许改：
绝对不能改：
验收方式：
```

如果 AI 没有软件/仓库连接，必须输出操作单或补丁建议，不得假装已经修改。

## 3. 环境搭建提示模板

```text
我们在做一个原创的固定/有限高角度风格化3D小游戏。
视觉规则：干净、自然、温暖、颜色受控、柔和材质、细节成簇且有留白。
参考只用于提炼规则，不复制具体资产或布局。

当前场景：
[描述/截图/节点]

本次只做：
[例如：把灰盒入口改成一条暖土主路 + 一栋小屋 + 两组树石簇]

必须保持：
- 玩家走跑跳
- 十星拾取逻辑
- 当前固定镜头基线
- 主路/落点净空
- 不新增第三方依赖

请先：
1. 给两个局部方案，不超过5项差异；
2. 说明你会改哪些节点/文件；
3. 选择最小可逆方案做初稿；
4. 给我“第一眼看什么”的验收点；
5. 没有真实运行证据就明确写未验证。
```

## 4. 资产二开提示模板

```text
这是一个来源和修改许可已核对的资产基底。
目标风格：干净的高角度风格化自然世界。
游戏机位：[说明或截图]

请先把建议分三栏：
- 保留：已经符合目标的结构
- 修改：真正影响固定机位观感的3项以内
- 不做：看不到/收益很低的细节

优先级必须是：
大形/比例 → 模块替换 → 配色 → 材质 → 有限细修。

不要为了“原创”重做整件模型。
每一步都写恢复办法；最后列出回Godot要检查的尺度、原点、碰撞、材质和实际机位观感。
```

## 5. 风格统一提示模板

```text
我有A/B两件资产，要让它们像同一个世界。
固定相机和灯光，不要同时改变几何和光照。

依次只处理：
1. 色盘关系；
2. Roughness/Metallic层级；
3. 边缘语言；
4. 细节密度。

每轮只改一类关系，给出前后差异和恢复方式。
“全部使用同一个材质值”不是合格方案。
最后做缩小图检查：主路/角色/焦点是否比背景更先被看到。
```

## 6. 细节打磨提示模板

```text
现在功能已经成立，不允许扩需求。
请把画面问题按影响排序，只选最高的一个：

- 构图/主次
- 比例/轮廓
- 配色
- 材质
- 植被密度
- 灯光
- VFX
- 性能/兼容

先解释为什么它是当前最大问题，再给一个可撤销修改。
修改后同时检查：
1. 是否更好看；
2. 是否更干净；
3. 是否仍然好玩；
4. 是否破坏旧功能。
没有明显收益就回退，不继续堆细节。
```

## 7. AI产出三种结论

### 可采纳
范围正确、有实际证据、旧功能回归通过、没有隐藏扩大需求。

### 需修改
方向对，但强度、范围、可读性、性能或资源引用仍有问题。

### 证据不足
只有代码/截图/口头推断，没有在目标版本/机位/设备验证。

“证据不足”不是失败，也不是默认采纳。

## 8. 排错时禁止“一口气重写”

使用：

```text
现象：
原本应该：
刚改过：
保持不变：
请只提出1–3个候选原因。
先设计一个能区分原因的最小实验，不先重构。
实验后根据实际结果再继续。
```

## 9. 我们最重要的 AI 协作能力

最终学员应该能说：

> 我知道我要什么；我知道为什么把这一步交给AI；我知道AI改了哪里；我看过真实结果；我知道什么没验证；如果不对，我能把范围缩小、回退并继续。
