# B01｜3D 空间与 Transform

## 课程定位

这是整个课程的第一课。

不要把它做成“3D 数学入门”，而要让一个从未系统学习 3D 的人，在 30–45 分钟内建立足够的空间直觉，并能够立刻进入 Godot / Blender 操作。

本课唯一目标：

> **看得懂、说得出、调得动 3D 物体最基础的空间参数。**

---

# 学习者画像

学习者：

- 没有 3D 美术专业背景
- 会使用 AI 辅助编程
- 不希望先学大量数学和理论
- 希望知道“这个东西能做什么、参数改变后会发生什么”
- 最终希望使用 Godot + Blender + AI 开发 3D 游戏

教学语言：中文。

专业词保留英文，并在第一次出现时给中文人话解释。

---

# 本课最终能力

完成本课后，学习者必须能够：

1. 看到 X / Y / Z 轴时知道它们表示 3D 空间的三个方向。
2. 判断应该使用 Position、Rotation 还是 Scale 来完成一个简单需求。
3. 理解 Transform 是位置、旋转、缩放等空间信息的整体概念。
4. 通过互动观察 Local 与 Global 坐标的区别。
5. 理解 Origin / Pivot 为什么会影响旋转与缩放。
6. 在 Godot Inspector 和 Blender Transform 面板中主动修改这些参数。
7. 能用正确术语向 AI 描述“物体位置不对、旋转中心不对、尺寸不对”等问题。

---

# 知识分级

## A｜必须掌握

### X / Y / Z Axis

人话：3D 世界里用三个互相垂直的方向描述空间。

本课不要求记不同软件所有轴向约定，但必须注意：不同软件 / 引擎对“前方”方向的约定可能不同。

### Position

人话：物体在哪里。

### Rotation

人话：物体朝哪个方向、转了多少。

### Scale

人话：物体在各个轴上放大或缩小多少。

### Transform

人话：描述一个物体在 3D 空间中“在哪、怎么转、大小如何”的核心空间信息集合。

### Local Space

人话：以物体自己当前的方向作为参考。

### Global / World Space

人话：以整个世界固定方向作为参考。

### Origin / Pivot

人话：旋转、缩放时围绕的参考点。

---

## B｜必须认识

- Translation：很多软件 / 文档中指位置移动。
- Gizmo：视口中用于拖动、旋转、缩放的轴向操作器。
- Apply Transform：把当前变换“应用”为新的基准状态；本课只理解用途，不深入底层。

---

## C｜用到再学

- Quaternion
- Euler Rotation 顺序细节
- Transform Matrix
- Basis
- Quaternion / Matrix 相互转换

---

## D｜本课禁止展开

不要讲：

- 矩阵乘法
- 三角函数推导
- 四元数数学
- 欧拉角万向节锁的深入原理
- Godot Transform3D API 完整接口

可以一句话告诉学习者“以后复杂旋转会遇到这些”，然后结束。

# OpenMAIC 课堂结构

## Scene 1｜先看结果：你其实每天都在用 Transform

展示一个简单 3D 小场景：地面、Cube、一个箭头或小机器人。

AI 老师连续做三件事：

1. 把 Cube 从左边移动到右边。
2. 把 Cube 旋转 45°。
3. 把 Cube 拉高。

然后问学习者：

> “刚才三个变化分别属于 Position、Rotation、Scale 中的哪一个？”

不要先讲定义。

---

## Scene 2｜X / Y / Z：给 3D 世界装上坐标尺

使用可旋转的 3D 场景显示三根明显的坐标轴。

学习者可以旋转观察视角。

要求：

- X / Y / Z 清楚标注
- Cube 初始位于原点附近
- 点击 X / Y / Z 后，让 Cube 沿对应轴移动
- 屏幕同时显示 Position 数值变化

核心体验：

> “数字改变”和“物体在空间中的移动”是同一件事的两种表达。

---

## Scene 3｜Position / Rotation / Scale 参数实验

这是本课最重要的互动。

提供一个 Cube，并提供以下控制：

### Position

- X：-5 到 5
- Y：0 到 5
- Z：-5 到 5

### Rotation

- X：-180° 到 180°
- Y：-180° 到 180°
- Z：-180° 到 180°

### Scale

- X：0.2 到 3
- Y：0.2 到 3
- Z：0.2 到 3

每次拖动立即反馈。

加入 Reset 按钮。

AI 老师不要长篇解释，只需要提示学习者完成三个任务：

1. 把 Cube 放到右上方。
2. 让 Cube 绕竖直方向旋转约 45°。
3. 把 Cube 变成长方体。

---

## Scene 4｜Local vs Global：最容易“看文字还是不懂”的概念

使用一个箭头形物体或有明显朝向的小机器人，不要使用完全对称的球。

步骤：

1. 初始朝前。
2. 将物体旋转 45°。
3. 显示 Global 轴。
4. 显示 Local 轴。
5. 切换 Local / Global，并沿“前方轴”移动。

让学习者观察：

- Global 轴不随物体旋转。
- Local 轴跟着物体旋转。

完成后让学习者选择：

> “一辆已经转弯的汽车想继续沿自己的车头方向前进，更接近 Local 还是 Global 思维？”

正确答案：Local。

---

## Scene 5｜Origin / Pivot：为什么我的门从中间旋转？

这是本课第二个重要互动。

显示一扇简单长方形门。

提供两个按钮：

- Pivot 在门中心
- Pivot 在门侧边铰链位置

播放相同的 90° Rotation。

让学习者直接观察：

- Pivot 在中心：门像风车一样从中间转。
- Pivot 在铰链：像正常的门一样打开。

AI 老师总结一句：

> “很多看起来像动画或代码问题的 Bug，其实只是 Pivot / Origin 放错了。”

---

## Scene 6｜错误诊断小游戏

给出 4 个情境，每题先让学习者判断，再解释。

### 情境 A

“模型位置正确，但比整个场景大 100 倍。”

优先检查：Scale / 导入单位。

### 情境 B

“一扇门旋转时绕中心转，而不是绕门轴。”

优先检查：Origin / Pivot。

### 情境 C

“角色已经转向，但代码让它始终沿世界固定方向移动。”

需要想到：Local / Global。

### 情境 D

“我只想把物体往右移动，AI 却修改了模型顶点。”

优先应该修改：Position / Transform，而不是重新建模。

---

## Scene 7｜离开课堂，进入真实软件

课堂最后不要继续讲理论。

显示两个任务：

### Godot

创建一个 Node3D + MeshInstance3D(Cube)，在 Inspector 中修改 Position / Rotation / Scale。

### Blender

使用默认 Cube，在 Transform 面板重复相同实验，并观察 Origin。

告诉学习者：真正的学习将在软件里完成。

# Quiz 设计

总共 6–8 题即可。

不要问：

> “Transform 的定义是什么？”

优先问实际场景。

示例：

1. 想让宝箱从地面移动到桌子上，首先修改什么？
2. 想让一块木板更长，应该修改什么？
3. 门绕错误位置旋转，首先检查什么？
4. 汽车转弯后继续沿车头前进，更接近 Local 还是 Global？
5. AI 说“把角色 Scale 设置成 100 才能看见”，你是否应该立即接受？为什么？
6. Blender 中模型看起来正常，但进入游戏后尺寸异常，你首先会想到哪些 Transform / 单位相关问题？

最后两题允许开放式回答，由 AI 老师评分。

---

# AI 同学互动设计

AI 同学不要频繁插话。

只安排两次有价值的“外行问题”：

### 第一次

> “Position 和直接在 Blender Edit Mode 里移动顶点，不都是移动吗？”

AI 老师回答重点：

一个是移动整个对象 Transform，一个是在改变 Mesh 自身形状；游戏开发中这两个概念必须区分。

### 第二次

> “我让 AI 帮我改 Pivot 不就行了吗，为什么自己还需要懂？”

AI 老师回答重点：

因为你至少要能识别“这个症状像 Pivot 问题”，否则无法给 AI 正确上下文，也无法判断修复是否正确。

---

# 人必须亲自做的事情

本课不允许完全交给 AI：

- 自己拖一次 Position X / Y / Z
- 自己拖一次 Rotation
- 自己把 Scale 改得明显错误再恢复
- 自己切换 Local / Global 观察 Gizmo
- 自己移动一次 Origin / Pivot 或至少观察不同 Pivot 的效果

原因：这些属于空间直觉，必须通过视觉和操作建立。

---

# 外行最容易忽略的点

## 1. Scale = 1 不代表“1 米大”

Scale 是相对比例；真实尺寸还涉及 Mesh 尺寸、单位、导入设置。

## 2. 看起来位置对，不代表 Origin 对

Origin / Pivot 可能远离可见模型，直到旋转 / 缩放时才暴露问题。

## 3. Transform 和编辑 Mesh 不是一件事

移动 Object 与移动 Mesh 顶点会产生不同后果。

## 4. Blender 与游戏引擎坐标约定可能不同

不要靠死记“哪个轴一定是前方”，要学会看 Gizmo / 文档 / 导入结果。

## 5. 非均匀 Scale 以后可能影响物理、法线、子节点或资产工作流

初级阶段只需知道：如果准备把 Blender 资产导入游戏，应该开始形成检查 / Apply Transform 的习惯。

---

# 性能意识

本课几乎没有性能压力。

但需要建立第一个工程意识：

> 不要因为模型尺寸 / Transform 错误，就用越来越怪的代码和参数去“补偿”。

资产管线中的基础错误越晚修，返工越大。

# 本课结束时应该会说的专业话

学习者应该能够自然表达：

> “这个物体 Mesh 本身看起来没问题，更像是 Transform 或导入 Scale 有问题。”

> “门的 Rotation 数值没问题，但是 Pivot 在中心，所以旋转方式不对。”

> “角色已经转向了，如果希望它沿自己的前方走，我要确认代码用的是 Local 方向，而不是固定的 Global 方向。”

达到这种表达水平，本课通过。
