# 从零到真正干活：先理解，再诊断，再和AI生产

对象：没做过3D游戏、或只试过一点的人。已有设计审美也不要求从零雕刻、绑骨架或背API。最终目标是固定/有限高角度、干净、配色受控的风格化小世界；美术以套装选择、二开、组合和统一为主。

## 只需要知道这三个入口

|你现在想做什么|打开什么|做到哪里停|
|---|---|---|
|学一个概念|[课程索引](lesson-index.md)当前课的OpenMAIC全文；课堂后打开该课“概念Lab”|能预测一次变化、做一次对照并解释，不必做完整游戏|
|检查是否真正记住|[单元/阶段检查点](../assessments/unit-checkpoints.md)和[记忆卡](../print/essential-memory.md)|找出一至两个具体缺口，补练后换条件再验|
|开始真实开发|[生产任务单](production-work-orders.md)，配[AI指挥手册](ai-build-playbook.md)|当前任务的产物、回归、恢复点明确，再接受下一项工作|

不用先读全仓库。首次从A01开始；能证明已有能力的学员可以先诊断、跳过已掌握部分，但不能以“做过类似项目”代替关键证据。

## 一节课的实际节奏

看一个现象或短示范 → 用自己的话预测 → 课堂控件试一次 → 打开小型Godot/Blender实验做同类对照 → 离开答案解释原因 → 留下一条进度。

第一次不会很正常：AI先示范一个小步骤，再让你换一个数值或对象；熟悉后只给目标；检查掌握时用未展示的变式。不会从第一课就让新手独立排错整款游戏。

课堂讲解与软件实验必须使用同一个核心问题。比如课堂比较“隐藏墙/禁用形状”，软件也先只做这两个动作，不突然要求写完整控制器。没有软件时可以学概念，但软件应用保持待验证。

## 什么时候进入正式项目

A01–A08是空间、职责、移动和镜头底座。B01–B12补上基础视觉、资产往返、事件状态、回归与AI验收。B13本身就是基础阶段综合任务，不再另外增加一场相同考试。

**通过基础阶段相应关键M后，就可以开始按生产任务单开发。不要等全部47课结束。** C/D围绕正在遇到的地图、角色、资产二开、风格统一和交付任务按需学习；先检查课内前置。D01–D04仍是美术生产主线，不因采用套装而取消；D05–D06战斗增强和E组专题不阻塞基础版。

“进入项目”也不等于第一次打开项目：基础课已在参考/副本中迁移。区别是之前为了理解，之后为了交付一个可用版本。成品参考可用来观察，不拿完整答案仓库当独立考试起点。

## 记忆与复习，不让考试吞掉创作时间

每课最多优先回忆两条当前M规则，K只知道用途。下次会话抽一个旧关键判断，隔几次再换对象查一次；间隔随错误、使用频率和遗忘情况调整，不宣称某个天数是所有人的最优规律。

单元检查替代当次重复随堂题，基础阶段检查复用已可靠的证据。一次综合操作可以证明几个概念；不把P/D/T和旧题库全部累加成作业。

记不清词、菜单不熟、概念理解错误、没装软件、结果未保存是不同问题。补练要对症，不给人贴“基础差”的标签。

## 一条真实的完成记录

“我选择只改屋顶比例；AI调整了Variant_Roof；固定镜头下入口更清楚；碰撞包装未改；重新导出后走跳仍成立。”

这比“本课已学完”更有用。简记即可，截图/日志按需；个人记录保存在本地，不提交到公开仓库。

## 教学依据与边界

本设计借鉴示范与练习交替、图文结合、抽象与具体对应、检索练习和间隔复习。[IES学习指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)支持这些一般做法，证据强度不一；它没有验证本课程、OpenMAIC或AI评分，也不证明这是唯一“最先进”的方案。

软件控件是否正确、AI反馈是否适当、新手是否能独立迁移，需要代表课堂与真实学员试走。课程文案和自动检查通过不等于教学效果通过。
