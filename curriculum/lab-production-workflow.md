# 概念实验室与正式项目：两条线，不混在一起

课程从现在开始明确区分两种软件实操。二者都重要，但目的不同。

## 1. 概念实验室：为了看清因果

概念实验室可以故意很小、很人工。目标是让学习者在 5–15 分钟内改变一两个参数，马上看到结果并能复位。

实验室允许：

- 两个球、一个门、一个碰撞墙这种“教学场景”。
- 滑杆、开关、A/B 对照和极端值。
- 为了说明概念而暴露现实项目里不会直接给玩家看的参数。
- 同一个实验文件被多节课复用。

实验室不要求：

- 像正式游戏一样组织全部节点和资产。
- 为了教学演示而复制一整套商业项目架构。
- 每课都做一个独立大场景。

### 当前 Godot 实验文件

|课/概念|文件|亲手改变什么|看什么|
|---|---|---|---|
|A02/A07 空间、父子、门轴|`game/scenes/lab.tscn`|Position/Rotation/Scale、父空间、Pivot|世界/父/自身方向和门轴差异|
|A04/B06 可见/阻挡/Trigger|`game/labs/collision_roles_lab.tscn`|目标位置、Visual、Collision、Trigger|看得见不等于阻挡；阻挡不等于事件|

### 当前 Blender 实验文件

`blender/labs/` 采用“真实 `.blend` + 可重建 Python 源”的方式。

- `transform_origin_lab.blend`：中心 Origin / 侧边 Origin、旋转门轴、Applied / Unapplied Scale。
- `kitbash_style_lab.blend`：基础小屋与二开变体，练比例、模块替换、配色、Roughness 与细节密度。
- `build_labs.py`：上述 `.blend` 的可重建源；不要把二进制文件当不可解释黑盒。

Blender 实验主要训练“看、选、改、回退”，不要求背 Python。

## 2. 正式项目：按真实生产流程干活

正式项目是 `game/scenes/main.tscn` 所代表的“星光小庭院”。这里不为了讲概念随意拆结构，而按一个小型商业原型/独立 Demo 的现实流程推进。

### P0 方向与约束

先确定：游戏目标、固定/有限镜头、目标平台、参考图、风格卡、范围停止线、第三方资产策略。

这一步**不做精模**。只要回答：我们做什么、不做什么、玩家怎么看世界。

### P1 灰盒与尺度

用 Box/Capsule/Plane 等代理：

- 路线和区域大小。
- 门、坡、平台、跳跃距离。
- 固定镜头和玩家在屏幕中的尺寸。
- 角色跑起来是否有空间。

验收是“路线、尺度、构图能工作”，不是漂亮。

### P2 核心玩法与状态

在代理资产上先完成：

- 走/跑/跳。
- 碰撞与 Trigger。
- 十星收集。
- 完成、UI、重开。
- 必要状态和事件边界。

此时美术仍可很丑，但玩法必须可重复验证。

### P3 可玩灰盒回归

把完整小循环从头走到尾。修路线、镜头、碰撞和逻辑，不在这时靠精美资产掩盖结构问题。

通过条件：不依赖开发者作弊也能完成一轮。

### P4 美术竖切片（Art Spike）

**不是立刻替换整张地图。** 选一个 10–20 秒会经过的转角，只替换：

- 一棵树。
- 一栋小屋或一个建筑模块。
- 一块石头/生活道具。
- 一小段地面与植被。

用候选素材包 + Blender 二开 + Godot 固定机位，验证我们的资产管线和视觉目标真的能达到预期。

如果这个角落做不到 80 分，不批量采购和替换。

### P5 资产采购与导入合同

竖切片通过后，才锁主环境套装。每类资产进入项目前记录：来源/许可、单位、朝向、Origin、材质槽、纹理、碰撞策略、可编辑主文件、导出格式。

AI可以整理清单和批量检查；人决定是否买、是否采纳以及风格是否合格。

### P6 Blender 二开与模块化

对资产按：

**用途/镜头 → 大形比例 → 模块替换/Kitbash → 配色 → 材质 → 有限细修**

处理。看不到的细节不优先；不为“原创”从零重建合格资产。

### P7 分批替换代理资产

一次替换一个资产家族，例如先树，再建筑，再石头/道具。每批都：

1. 固定同一玩家机位做 A/B。
2. 检查尺度、碰撞、路径、交互。
3. 检查共享材质和资源影响范围。
4. 回归完整收集循环。

不要“一键全地图换皮”。

### P8 风格统一与 Set Dressing

先统一：比例/轮廓 → 色盘 → 材质语言 → 细节密度。

然后才补花草、围栏、桶、篮子、路牌等生活细节。细节以“簇”组织，并持续做缩小图检查。**减法是正式工作，不是失败。**

### P9 灯光、后处理、VFX、音效

结构和资产稳定后才做最终表现：主光、环境、Fog/Glow、粒子、Trail、音效、短促 Camera impulse/FOV Pulse 等。

每次只解决一个问题；后处理不能用来遮住错误的配色、材质或构图。

### P10 角色/动作与可选战斗

现成角色和动作先在最小测试里完成兼容/重定向，再接正式状态机；攻击表现分成动作、命中判定、反馈三个职责。最后才加训练木桩等可选战斗内容。

### P11 性能、目标平台和交付

固定设备/分辨率记录性能，做一项一项的比较；检查导出、输入、窗口、存档/设置和恢复。最后才算完整 Demo。

## 3. 为什么不是“先把所有逻辑做完，再想美术”

正确流程不是美术最后才出现，而是：

- **早期**先用参考、镜头和风格卡约束尺度与构图。
- **中期**核心逻辑用代理资产完成。
- **逻辑稳定后**做一个小型美术竖切片，验证采购/二开/导入管线。
- **竖切片通过后**才批量生产和替换。
- **最后**才进入 Set Dressing、灯光、VFX 和微调。

这样既不会“先精美建模，后来关卡全推倒”，也不会“程序做完以后发现资产根本不适合镜头”。

## 4. AI在两条线里的角色不同

### 概念实验室

AI像老师/实验助手：给一个预测问题，帮你暴露参数，提醒固定变量，解释观察结果。重点是**你懂不懂因果**。

### 正式项目

AI像工程/美术执行助手：根据当前 milestone 做局部改动、列影响范围、跑测试、整理素材、批量处理。重点是**项目有没有按阶段通过 Gate**。

正式项目里 AI 不应该因为看到“更漂亮”的可能性就跳过灰盒、重写系统或批量换资产。

## 5. 每个阶段都用 Gate，而不是“感觉差不多”

每个阶段结束记录：

```text
阶段：
目标：
通过证据：
仍未验证：
这阶段禁止带到下一阶段的问题：
允许进入下一阶段的范围：
回退点：
```

只要 Gate 没过，就先修当前问题。这样 AI 也更容易被约束在正确范围内。
