# 三节详细互动工作坊：B04 / B08 / B10

这是教学规格，不表示新版OpenMAIC课堂已经生成。课前记录使用版本，先完成一个样板再扩展。生成输入可由本节的目标、场景、题目和验收组合而成。

## B04 · 看得见，为什么穿过去？

必须掌握C06/C07；应该了解Box/Capsule/Convex用途；复杂凹面动态碰撞后置。

**起始状态：** `game/scenes/main.tscn` 中玩家、地面、墙。墙的Mesh和Shape分开；玩家第2层、Mask第1层，星星Mask第2层。备份场景再改，不改原样例。

**先预测：** 只隐藏墙Mesh，还能挡人吗？只关闭墙Shape呢？C06-P要求说出两次结果，答题前不运行。

**操作：** ①运行撞墙并记位置；②停止，仅取消Wall/Mesh的Visible，运行再撞；③恢复可见，仅禁用Wall/Shape，运行通过；④恢复并核对diff只涉及一个参数。启用Debug的可见碰撞形状帮助观察，但不能把调试线当美术。

**故障：** 星星Mask从2改为1。先查“谁扫描谁”，再查monitoring、形状、Signal与过滤。不能把所有Layer全开冒充修复。

**迁移：** 把墙换成树；决定树干、树叶哪些真需要碰撞，给出玩法理由。C07-T答对还要实际排查一个随机故障。

**OpenMAIC呈现：** 拆分视觉/阻挡/检测三个开关，明确只是示意模型，不能用网页自定义物理断言Godot行为。题后必须回到真实场景。

**验收：** 三组对照证据；一处Mask故障诊断；恢复正常后人物不穿墙，星星可拾取。性能提醒：碰撞形状按用途简化，而不是“所有复杂形状绝对禁用”。

## B08 · 金属、塑料和发光，不是三个颜色

必须掌握C12/C13；应该了解PBR、Normal Map用途；BRDF、GI内部算法放到后续。

**起始状态：** 打开 `game/labs/material_lab.tscn`，F6。左球可调，右球固定。记录版本、渲染器、相机与环境；参数0.4 Roughness / 0 Metallic / 0 Emission。

**先预测：** 更亮的塑料一定要Metallic=1吗？提高Emission地板一定会亮吗？用户先答C12-P与C13-P。

**操作：** ①固定Metallic=0，Roughness从0.1到0.9；②恢复，固定Roughness=0.4，Metallic从0到1；③恢复，Emission从0到4；④不再改材质，单独打开真实OmniLight。对照高光宽度、反射、表面亮度和地板受光。

**故障：** 两球一起变色时先查共享Resource。演示代码给参考球复制材质；不要把“实例了两个球”当自动资源独立。

**迁移：** 为塑料玩具、裸铁、锈斑分别写参数方向和理由。锈层通常按非金属考虑；不用“整把剑必须Metallic=1”的口诀。参数区间是实验，不是配方定律。

**OpenMAIC呈现：** 优先真正3D材质渲染。若只能画颜色圆，不允许冒充粗糙度/金属效果；转为讲解并引导运行Godot实验。不要承诺所有渲染器都有相同Glow/GI。

**验收：** 一次只动一项的对照记录；能区分Emission、Glow、真实照明；用不同物体解释，而不复述滑条定义。

## B10 · 星星只能算一次

必须掌握C16；复习C05/C06/C07。应该了解queue_free是延迟释放；不讲大型事件总线或复杂架构。

**起始状态：** 5颗星的参考场景。每颗星为Area3D，简单SphereShape3D检测，旋转只作用Visual；Mesh与触发区域不同。

**先预测：** 同一帧连续两次调用拾取，计数应该多少？星星销毁后，谁保存计数？先答C16-P。

**操作：** ①正常拾取一次，计数+1；②用测试中的重复调用检查taken防重；③换一个不在player组的Node3D，计数不能变化；④收齐、重开、跌出地面回到出生点，各测一次。

**故障：** 去掉taken保护或不连接信号，每次只注入一项。复现后恢复。不要以“把计数限制在5”掩盖重复事件的根因。

**迁移：** 蓝色能量球改成加能量而不是星星分数。复用检测与防重思路，分清谁拥有状态，UI只显示。无需此时做完整背包。

**OpenMAIC呈现：** 用事件日志可视化进入、过滤、防重、发信号、更新状态、更新UI。用户先排列事件，再运行；不要让AI同学抢答。

**验收：** 正确对象一次计数、错误对象不计数、重复回调不加两次、重开归零、日志可解释。代码测试入口见 `game/tests/smoke.gd`；测试文件已提供不代表测试已经运行。
