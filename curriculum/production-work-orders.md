# 正式生产任务单：按交付问题工作，不按按钮顺序工作

与[概念实验室/项目区分](lab-production-workflow.md)配合。下列是适合本课程小型独立Demo的可迭代流程，不是所有工作室统一的唯一商业流程。阶段号P0–P11沿用现有项目记录，不新增课程编号。

**重要修正：**“最后精修”不等于美术、性能和兼容最后才看。早期就定镜头与风格，试目标设备导出；角色/动作是核心时在批量美术前先做兼容小试。P9是最终表现打磨，P10是完整动作接入，P11是最终交付，不是第一次验证这些风险。

## 任务顺序和验收口

|阶段|这次真实工作/产物|人负责的决定|AI可交付|进入下一步的证据|
|---|---|---|---|---|
|P0 约束|一页目标、范围、风格与目标设备；初始化可恢复副本|玩法终点、视角、预算、禁做项|最小目录/场景方案、候选资产缺口|范围可复述；空项目能在目标平台试导出，不保证所有效果可用|
|P1 灰盒|路线、门宽、坡/平台、镜头和代理角色|尺度、路径和屏幕可读性|灰盒布局/可调控制参数|用实际输入走一圈，记录卡住与遮挡点|
|P2 逻辑|十星、完成、重开、最小反馈/UI|状态规则、谁负责什么|局部实现和正反例测试|重复拾取不重复记分；重开后再收第一颗；初次性能基线|
|P3 灰盒回归|完整收集循环的可重复版本|先修阻塞问题，不加范围|测试/差异/已知问题摘要|实际走通，不以测试脚本传送采集代替人走通|
|P4 美术小样|一棵树、一栋小屋、一块石头和一小段地面|参考规则、是否值得继续|替换一个样本、导入设置和A/B|同机位看过；改源后重导入两次；近远距离、风格、成本可接受|
|P5 采购合同|锁主套装及补缺清单，保留来源和修改许可|是否购买、哪些值得二开|目录、命名、格式、许可待核项整理|首次使用前已核对许可；公开仓库再分发另验；资产不依赖无法移植的核心效果|
|P6 二开|比例/部件/颜色/材质的一件合格变体|保留、改哪里、哪里不做|局部Blender编辑与导出|原版未覆盖；变化可见；相邻对象未意外改；功能包装未损|
|P7 分批替换|每批一个资产家族，不整图重做|批次范围和视觉差异是否采纳|小批替换、清单、回归|角色/路/目标仍可读；碰撞/交互/重开正确；有回退点|
|P8 风格与布置|统一大色块、边缘/材质、细节簇和留白|减哪些细节、焦点在哪里|样板扩展与受控变体|缩略图/游戏距离对照；不是靠全场发光“救”可读性|
|P9 表现精修|光照、必要雾/Glow、粒子、声音与UI|效果是否解决问题、强度和舒适度|单效果开关与预设、恢复参数|低运动/静音仍能知道结果；效果可关，参数能保存后重开|
|P10 动作增强|已早试兼容的角色/动作接入；可选木桩|动作节奏、命中规则、是否需要增强|融合、时序、反馈分层与测试|空挥/同击/下一击/取消恢复分开验证；禁用战斗主线照常|
|P11 交付|目标设备构建、说明、来源清单、已知限制|是否交付、什么问题必须先修|打包与日志、环境/版本记录|另一人能启动和完成；实际设备性能证据；保存/恢复与输入检查|

未过关键验收口就修当前问题；与当前无关的选修缺口不阻止继续。场景截图漂亮不等于路线可达，headless通过不等于人眼舒适。美术采纳是设计判断，不把个人80分变成通用学习及格线。

## 第一张任务单：从参考项目退回自己的灰盒

```text
当前任务：P1灰盒，不是精美建模。
目标：固定/有限高角度镜头下，角色能沿主路从入口到平台再返回。
材料：我已提供的工程副本、当前版本、风格约束与实际截图。
你先读取工程，指出现有结构和待验证项，不凭README声称已经跑过。
本次只允许改路线代理、镜头基线及必要碰撞，不改收集/完成/重开规则。
先列最小改动和如何恢复；一次实现一个可试片段后停下。
我负责选择路线和镜头，亲自试走；你协助列遮挡/卡点并记录。
验收：不用开发者传送也走得通，平台落点可见，没有新依赖或未授权素材。
不满足就留在P1；不要加天气、精细植被或战斗来代替修复。
```

## 第二张任务单：一件视觉资产往返

```text
当前任务：P4小样，先不批量采购。
目标：将一件来源许可已核对的视觉模型放入现有功能包装。
先检查尺寸、前向、原点、材质与绑定情况。只改Visual入口，不改事件ID、碰撞层、任务计数。
我先选需要改变的一项比例或颜色；你执行并保留源副本/导出设置。
验收分开做：导入存在→固定机位效果→实际功能→第二次修改源文件重导入后仍成立。
如原模型单位/骨架不适配，先报告原因和替代方案，不一键Apply所有变换。
没有Blender/Godot连接就给我可执行操作单，不假称已经调整。
```

## 第三张任务单：像实际项目一样收尾

```text
当前任务：已有可玩且统一的一个区域，只做一次精修。
先按“阻塞玩法/可读性与舒适/风格不一致/纯装饰”列问题，不发散需求。
只选当前最值得修的一项，说明收益、可能成本和恢复点；由我确认取舍。
同机位与同设置留前后对照；可以删细节，不以模型数量当完成度。
修后列实际验证、未验证和旧功能回归，没收益就恢复。
停止条件：达成本张任务单的验收，不继续无限“优化”。
```

## 每次开发只留六项交接

任务目标；改动范围；使用的参考/资产来源；验证证据与未测项；选定值和恢复点；下一唯一任务。AI写长文不加分，学员能据此继续工作才有价值。

角色尺寸/骨架、透明植被、Shader和导出平台风险随首次出现即验证，不拘泥于表格先后。资产替换、试玩、性能测量会反复穿插。这训练的是取舍与反馈循环，不是瀑布式“程序全完了美术才开始”。
