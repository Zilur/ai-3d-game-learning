# 未来成长指南：从入门作品到小型商业级游戏

版本：2026-09-16。面向孩子与深度参与的成人；这是成长路线和项目验收设计，不是新增必修课、商业成功承诺，或已完成的高级课程。

[入门终点与美术停止线](depth-and-growth.md) · [知识范围、深度与学法](growth-knowledge-map.md) · [本轮工作单](templates/growth-cycle.md) · [发布检查](templates/release-readiness.md) · [使用入口](README.md)

## 1. 远期目标要写清，但不给孩子背上销量目标

**远期目标：能够主导制作一个范围受控、体验完整、质量稳定、承诺真实、来源清楚、可以维护的小型商业级游戏。** 可以继续使用固定/有限视角、风格化自然世界和资产套装二开，不以从零做所有素材、写所有代码或换更复杂引擎证明专业。

“商业级”在这里是我们的工作定义，不是行业统一认证。质量就绪、平台允许上架、真实商业成绩是三回事：作品完成不等于获准发布，商店审核通过不等于好玩或有销量。以下路线中的通过均需具体证据，不产生自动商业认证。

商业化是将来的自主选项，不是孩子的毕业条件。可以选择免费发布、只向亲友展示或做下一个作品。成人负责对外账户、合同、付款、预算和规则核对；不替孩子承诺营收，不以收入、愿望单或排名评价孩子。不为了练商业化而默认加入广告、抽奖、内购、联网或运行时大模型。

## 2. 不变的学习循环，逐步提高的自主性

**创作愿望 → 一个可观察问题 → 先作预测 → 补足必要知识 → 最小实验 → AI协作实现 → 自己解释与验收 → 他人试玩 → 保留、修改、缩减或放弃 → 延迟迁移。**

入门多用短示范、现象对照和爸爸支架；进阶改为孩子提出假设、画系统关系、比较两种方案、设计测试。成熟阶段围绕真实玩家和可维护性决策。支架可以逐渐减少，也可以因新问题临时恢复，不把不给帮助当成目标。

不是“所有知识都零散现查”。遇到反复出现的同类错误，暂停扩功能，用一个短专题系统补齐相关基础，再回到工程。每轮留下一个可复用的概念模型、一个反例和一个检查方法。现象→机制→边界→取舍→迁移，是深度方向，不是每次必须上满五节课。

示范、教练支持、表达、反思与逐步撤去帮助参考认知学徒制；制作、分享和反思参考MIT创意学习路线。[1][2] 本项目的具体组合和节奏尚需真实试学，不能称为已证明最优。

## 3. 六个成长阶段：按作品证据推进，不按年龄或月份排队

阶段是工作类型，不是另一套课号，不改A01–E07，也不自动把原课K升级为M。已有相应证据可跳过或回到前一阶段；每一阶段都允许做完一个完整小作品就停下。商业路线不是必须连续走到底的流水线。

### 独立小作品（independent）：从照着做，到自己会安排

**进入条件：** 已能在当前小作品中完成相关判断和一条完整循环，不要求先上完47课。

**做什么：** 复用已会的镜头、控制器和合法素材，只换一个核心规则，做比第一作更小的作品。例：星星不再随意收集，而是按玩家选择的路线访问两个目标；没有现成工程时先用纸图和状态卡，不假称做完软件。

**补什么：** 需求边界、事件/条件/状态、简单代码阅读、恢复与打包。孩子先画规则和提出一条验收，再由AI实现。

**检查：** 孩子能解释哪些旧概念复用了、哪个知识缺口是新学的；一位未参与实现的人能开始、完成、重开。软件成功与独立理解分别记录。

**决定：** 证据足够就选择继续打磨或再做小作品；只能照搬时减少新增规则，补一个新变式，不回去重读全课程。

### 玩法原型（prototype）：先证明某种体验值得做

**做什么：** 写一句“给什么玩家、提供什么体验、凭什么区别于已有选择”。只验证一个核心互动，先用灰盒。参考同类作品的玩法与交互，不复制具体关卡或素材。

**例子：** 同一小庭院做两种路线：一条容易看懂，一条需要观察地标。先预测各自给什么体验，再让目标玩家选择与尝试。不要把玩法、速度、镜头、配色同时改掉后归因给其中一项。

**补什么：** 目标、反馈、节奏、风险与收益、关卡引导、玩家观察。爸爸先当设计伙伴，另找未参与设计的试玩者；开始可以每轮3–5位作定性排障，不用小样本百分比证明市场需求。

**检查：** 看玩家实际在哪停、误解了什么、有没有再次主动尝试，而不只问“好不好玩”。记录原话、行为和设计者解释的区别。没有满意原型就继续局部实验、改方向或停止，不用美术掩盖无趣。

### 目标品质样段（slice）：把一小段做成预期成品质量

Vertical slice在此指能贯通主要生产环节的代表性可玩样段，不是预渲染宣传片，也不是把全游戏先做粗糙。**小，是内容范围小；完整，是关键链路完整。**

**做什么：** 将原型的一小段做到目标品质：操作、引导、反馈、UI、音效、正式资产小样、设置、目标设备运行；需要保存进度的设计，加入最小持久化与恢复试验。短局不必强上复杂存档，但需明确退出与恢复承诺。

**补什么：** 清楚的状态归属、输入与表现分离、资源包装/重导入、音频层级、文本可读、低运动替代、性能预算、构建与回退。美术按够用停止线，不扩成专业建模课程。

**检查：** 用真实游玩路线检验画面；另选有代表性的低配置设备和压力情形。实际做第二个同类内容单元，记录制作、修复和回归成本，不只用第一个样段的感觉推算整作。

**决定：** 如果品质只能靠每次手工特例维持，或第二个单元成本超出成人认可的投入范围，先缩内容、改工艺或回原型；不要直接批量生产。

### 受控生产（production）：可复制地完成内容

**做什么：** 冻结一版范围和不做清单，将内容按最小可玩增量完成。每个增量都能运行、能回退，有功能和内容检查；新想法先放候选，不自动挤进当前版。

**补什么：** 数据驱动内容、职责与接口、资源依赖、任务拆分、版本控制、错误日志、自动回归、存档版本与兼容策略、可重复构建。只在重复和风险真正出现时抽象，不搭通用引擎或框架。

**检查：** 新内容不会破坏旧路线、输入、设置、存档和导出；至少能从干净检出及固定依赖重建。测试不能由AI一边改需求一边改断言“修绿”。范围、成本和已知风险由人复核。

**决定：** 核心体验与稳定性优先；需要砍功能时更新真实承诺，不以隐藏BUG冒充删减范围。阶段结束留一个内容完整的候选版本，而非永远新增系统。

### 候选发布（release）：从“我的电脑能玩”到“交给别人也可靠”

**做什么：** 停止非必要功能，按[发布检查单](templates/release-readiness.md)准备安装/解压运行、首次进入、正常游玩、退出重进、必要恢复、错误处理和支持说明。所有支持的平台、语言、输入方式都需要对应实测；未测试的不对外宣称支持。

**补什么：** 发布阻断项、测试矩阵、配置与存档迁移、商店表达、素材与依赖台账、真实截图/演示、已知限制、隐私和平台流程。外部规则在实际发布时再次查官方资料。

**检查：** 独立试玩者无需作者在旁解释即可获得所承诺的体验；已知严重崩溃、坏档、无法完成主流程、无权使用的资源等阻断项解决。小瑕疵按影响明确接受或修复，不要求“宇宙中绝无BUG”。

**决定：** 质量审核通过、商业投入决策、平台审批分别进行。可以先封闭测试或免费展示；不因已经花了时间就强行上线。

### 发布后维护（maintenance）：能负责地改进，也能结束维护

**做什么：** 复现反馈，按影响分级；用小补丁修复，写清变化，验证旧数据与回退。更新失败要有恢复方案；程序回滚不一定使新格式存档自动变回旧格式。

**补什么：** 缺陷分诊、版本迁移、用户沟通、支持边界、维护成本与复盘。对外联系由成人管理，不默认收集玩家个人信息或完整行为遥测。

**检查：** 一次修复能在原问题上复现并验证，又不伤害旧流程；维护说明真实。销售不佳时区分定位、曝光、价格、质量等假设，不把单一指标归罪于孩子能力。

**决定：** 继续局部改进、缩减维护承诺或结束这个项目并记录复盘；不是所有游戏都要持续运营。

## 4. 商业质量是多道门，不是一张总分表

本项目采用八个独立维度：玩家价值与体验、功能可靠性、数据与版本安全、目标设备与可用性、视觉与音频一致性、内容生产可持续性、来源与对外承诺、发布与维护准备。

每项只填“待验证、通过、阻断、不适用（需原因）”，并附构建版本、条件、证据、判断者和未测范围。漂亮画面不能抵消坏档；所有自动测试通过不能代替陌生玩家的操作体验；来源不清不能由“AI说可以用”抵消。详见发布检查单。

产品指标与学习指标分开：前者看真实作品与玩家，后者看孩子的解释、判断、迁移和提示依赖。孩子可以已经掌握某概念，但产品仍需大量内容工作；产品也可能被爸爸或AI做得很好，而孩子的部分能力尚待验证。

## 5. 知识范围扩大，但仍只给当前任务规定深度

原课程M/K不变。未来任务另写“本轮需独立负责的判断”“可借助工具完成的实施”“仅需认识的概念”“暂不进入的专项”。这是工作分工与深度说明，不是新评分体系。

开发者至少逐渐能追踪当前关键代码路径，读懂条件、容器、函数、事件和数据流，做小修改并核对测试。负责状态、存档或输入等关键模块时，需要进一步理解相关失败模式；不能永远只依赖AI解释AI自己的结果。

不要求所有方向都专家级。团队或外部专业帮助可以承担专项，但责任人仍需提出约束、读懂关键接口和证据，并知道何时不能独立验收。多人同步、复杂Shader、引擎底层与高阶美术只有明确需求才进入。详见[知识成长地图](growth-knowledge-map.md)。

## 6. 爸爸与AI在成长中怎样变化

孩子从讲“概念是什么意思”，逐渐讲“为什么选这个、另一个方案何时更好、证据还缺什么”。爸爸从示范和提问，逐渐转为设计评审、技术复核和风险守门；可以直接教，也可以接受孩子有证据的不同选择。

AI继续承担查找、草稿、局部实现和测试建议，但没有自评自批权。原有预设反问用于练习，真正独立迁移另换孩子未见的情境。对外试玩另找目标玩家，不把懂内情的爸爸当市场样本。

开会不用成人职场仪式：本轮只讲“我想改善什么、我凭什么认为会变好、这次实际看到什么、接下来删/改哪一项”。一个试玩、一个解释、一个检查可以同时支持多项证据，不重复填三份表。

## 7. 轻量计划、成本与商业现实

不承诺“几个月必出商业游戏”。由成人和孩子按现实可投入时间，为下一次小实验设可调整的时间盒；每次只推进一个风险最高的未知项。连续尝试仍无收益时，应重审假设或请人看一小段，不增加代码量赌运气。

先做一页作品说明：目标玩家、核心体验、范围、目标设备、参照品质、最大的风险、停止条件。成人另记素材、软件/服务、音频、本地化、测试、发布与维护的投入。复用不等于零成本，AI生成不等于零审核成本。

预算使用明确假设和不同情景，不把定性试玩换算成销量保证，不写固定“愿望单必转化”公式。儿童阶段不需要学习完整商业管理；只参与与作品选择相关的可理解取舍。预算、合同和法务需要时由成人核对真实地区与平台规则。

## 8. 平台只是发布渠道示例，不绑定现在的课程

以Steam官方资料为例：发布前需要商店页面和构建审核，页面的功能承诺应与可用内容一致。[3] 内容调查还区分随游戏交付并由玩家消费的预生成AI内容与运行时生成内容；后者涉及额外防护说明。[4] **AI辅助开发不等于必须在游戏运行时调用AI。**具体申报按实际内容及届时规则，不把历史口径硬编码为永久规定。

Steam Playtest可作为后期分发测试的一个渠道，不是必须的学习工具。[5] 输入、文字、对比度、音频和运动舒适性可参考微软的游戏无障碍指南，选适合实际游戏的条目实测，而不是宣称获得认证。[6]

这些官方资料在2026-09-16查阅。发布前重新检查平台、分级、年龄/账户、授权、隐私、费用与时间要求；本课程不替代平台审查或专业法律判断。

## 9. 今天怎样开始，而不把整本指南给孩子读

成人先选当前真正需要的一个阶段，在仓库根目录运行：

```sh
python3 tools/growth_workshop.py plan
python3 tools/growth_workshop.py session independent --cycle first-small-game
```

工具只生成`.learning/growth/first-small-game.md`：当前阶段的一页任务、已有课的查阅入口、亲子解释与检查、空白证据记录。只读公共课程配置，不自动读孩子旧日志、不调用AI、不修改game、不安排通知。已有同名文件不会覆盖；下一轮换cycle名即可。

由成人检查后把文件交给AI，一次只推进当前一步。需要生成互动概念课时加`--openmaic`；它给教师生成一段与当前风险对应的短课协议，不是已生成的课堂或商业游戏工程。

每轮新知识先用自由文字记录，已登记能力仍可走原family记录器；未登记专题不伪造A/E课号或混入原复习调度。只有经过真实任务和复测设计的新能力，才考虑将来扩展能力注册表。
