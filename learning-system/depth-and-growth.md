# 入门终点与长期进阶：少堆功能，逐步提高判断的深度

本页是本项目的进阶设计与使用规则，不是新增必修课，也不是已完成的高级课程。47课、ABCDE顺序编号、M/K要求、固定/有限镜头和资产套装二开路线保持不变。请结合[学习深度合同](../curriculum/learning-contract.md)、[原课程大纲](../curriculum/roadmap.md)和[爸爸陪伴指南](parent-guide.md)使用。

## 1. 这套课程的上限怎样理解

**当前课程定位：零基础进入AI辅助3D创作，完成一个范围受控、能够说明和验收的小作品。** A/B建立基本判断并做出完整循环；C/D用于扩图、资产整合和交付；E是遇到具体问题后的专项入口。课名里的“高级”是本课程内部的相对称呼，不等于专业岗位水平。

原课程已有每课的M/K、停止线、实操、迁移题和部分专项入口；但这些不等于已经提供从入门到专业的完整进阶训练。尤其是长期玩法设计、系统组织、实验方法和自主学习，需要跨项目反复练，而不只是把后面的章节读完。

本页补上“何时值得深入、深入哪一层、用什么小实验、怎样验收”。不把地图更大、术语更多、代码更长或效果更多当作进阶。没有真实试学与作品证据，不能宣布已达到这些层级。

## 2. 美术生产的停止线：能选、能拼、能统一、能小改、能维护

本项目不以培养专业建模师或原画师为默认目标。达到下面的实用条件，就应把主要精力转向玩法与系统，而不是继续刷建模技巧。

|能力|本项目的“够用”证据|
|---|---|
|选择资产|能按已有镜头、比例、色彩与材质规则选择套装，检查来源和使用条件，不因为单件漂亮就混入|
|拼装与二开|能调整静态部件的尺寸、比例、原点、连接和必要材质，保留可恢复的源文件|
|统一画面|同机位比较后，角色、主路和目标清楚，细节有主次；必要时删装饰，不靠堆后处理解决全部问题|
|接入与维护|导出、重导入与替换后，尺寸、碰撞、引用和旧功能仍符合约定；动作资源只先试一个兼容片段|
|实际验收|不仅截图好看，沿真实路线运行也不会持续遮住角色、误导方向或超过当前设备约束|

对应原课：A01、A08、B01–B05、B09–B10、C02–C03、C05、C07–C08、D01–D04；按需要取用，不把这个清单变成开始创作前的门槛。

复杂雕刻、完整角色手工建模、复杂UV、手工绑定、逐帧原创动画、渲染数学，不自动加入主线。只有兴趣明确，或现有资产确实不能满足作品需求时才开专项。

**停止的是无限加深美术制作工艺，不是停止审美与视觉沟通。** 玩家能否看清、风格是否一致、表现是否服务玩法，仍贯穿后续每个作品。美术达标不是永久认证，换镜头或玩法后应重新验收相关部分。

## 3. 长期真正值得打磨的六种能力

下表是后续训练建议。当前47课提供入口，不代表每项深度已经配齐专用Lab、教师脚本和参考解。

|长期能力与已有入口|什么时候深入|深入什么|推荐小实验与验收|
|---|---|---|---|
|玩法与玩家体验：A05–A08、B07、C01、C10、D06|功能正常，但玩家迷路、操作别扭、缺少选择或不愿再玩|目标、规则、反馈、节奏、风险与选择之间的关系|同一小地图做两种星星布局或反馈。先写各自预测，再请未参与设计的人试玩；记录具体停顿和误解，只改一处再试。不是按爸爸的审美偏好打分|
|因果与系统建模：A03–A07、B06、B08、C04–C06、C10–C11|两个功能一组合就相互破坏，或只能解释单个按钮|谁拥有状态、谁读取状态、事件顺序、共享与隔离、必须始终成立的规则|给已有收集循环增加一个最小条件。先画事件链或状态表，再检查重复请求、重开和中途退出；孩子能指出状态由谁修改，而不只照着AI解释|
|排错与实验：B11–B12、C09、E02|AI连续改动却说不清原因，结果偶尔成功或不同设备不一致|症状与根因、竞争假设、控制变量、测量条件、反例与证据局限|写两个可能原因，设计能区分它们的最小测试。记录修改前后与未验证项；不把“这次没出错”说成根因已证实|
|工程与交付：B05、B12–B13、C05、C11–C12、D03、D07|每加一件东西都复制多份逻辑，替换资产或发包容易坏|清楚的职责和接口、数据与表现分离、回归、版本恢复、范围管理|让AI局部重构一处重复逻辑，先列旧行为检查项，再验证调用方、资源引用、重开和导出。不以设计模式数量或框架大小验收|
|AI协作与证据判断：B12–B13、D07、E07及各课协作卡|任务一复杂，孩子就只能说“让AI再试试”|把模糊愿望变成约束；分小任务；比较方案；发现证据不足；决定接受、局部修复或回退|向AI提出同一小任务的两种方案。孩子先定标准，再比较影响范围、测试结果和代价；允许判断“两种都没证据，不采纳”，不要求每次抓到AI真错误|
|自主学习与迁移：各课变式、阶段检查及第二个小作品|在熟悉庭院会做，换主题就不会开始|识别相同结构、定位知识缺口、查一小段权威资料、设计最小验证、回到作品|保留控制器和资产库，做一个更小的新规则原型。孩子自己说出哪些旧概念可复用、哪一点必须新学，并用新例子验证；不自动推断已迁移到所有学科|

Godot官方的场景组织建议强调减少不必要依赖，优化指导强调先测量。这些是上述工程训练的技术依据，不是要求孩子立即学习引擎源码，也不证明本项目教学已经有效。[1][2]

## 4. “深入理解”不是堆新词：同一个概念逐层提高要求

以B06的一次性拾取为例。以下是父子探究路线，不要求一节课全部完成。

|层次|孩子需要能做什么|父亲或AI怎样引导|
|---|---|---|
|现象|验证一颗星星只计一次|先预测，再做一次正常与重复接触对照|
|机制|解释事件、条件、状态与显示的关系|请孩子画出谁检查、谁修改、谁显示；必要时一起读相关几行代码|
|边界|判断重复回调、重开、错误对象进入时应怎样|只换一个条件，先写必须保持的规则；本课程的重复回调不等于已经涉及多线程并发|
|取舍|说明状态放在物品、关卡或管理节点中的代价|只比较当前两种小方案，不引入通用事件框架；问“哪些调用方要改，怎样恢复？”|
|迁移|把相同规则用到钥匙、宝箱或一次性机关|换对象或规则，孩子先提出测试，再由AI辅助实现|
|专项|在真实需求触发时研究持久化、网络协调等更深问题|另开有边界的小实验；E06仍只是全K认识课，不能用讨论过联网认定掌握同步实现|

支持方式逐步减少：首次可看短示范和完整例子；随后只补剩余一步；再由孩子提出假设、测试和验收。卡住时可以恢复支架，不把“不给帮助”当成训练目的。示范、教练支持、表达、反思和逐步撤去帮助，参考认知学徒制的设计思路；本课程的具体应用仍需试学。[3]

**读代码与数学不会永远停在“AI来写”。** 当作品需要时，应逐渐能读懂相关变量、条件、函数、事件和状态变化，预测一小段逻辑的结果；空间运动问题再引入向量、比例、时间关系。先服务当前问题，再决定是否推公式或深入算法。不背API，并不等于永远不理解程序；也不要求在入门前学完一整套计算机科学。

## 5. 第一件作品之后怎样走

先完成一个范围很小但完整的作品；不用等47课全部学完才开始真实制作。随后建议做一次“同一作品的专项打磨”：例如只改善找路、操控或一次性规则中的一个问题，保留前后证据。

接着用原有镜头、资产库和控制器做第二个更小的原型，只换一个核心规则。第二作可以更短、更小；重点是孩子能否自己规划和迁移，不是继续扩大第一作。之后根据兴趣选择玩法设计、工程、技术美术、角色表现等方向，不要求全部深入。

每轮循环：孩子提出愿望 → 明确一个问题与成功条件 → 画出相关因果或规则 → AI辅助做最小方案 → 真实试玩或测试 → 根据证据修改或放弃 → 用自己的话复盘。

这是本项目建议的创作路径，与MIT Learning Creative Learning所强调的项目制作、分享和反思相呼应；不把一套方法名称当成效果保证。[4]

## 6. 一张可手写的进阶任务卡

只在作品遇到真实问题时使用，不要每课填表。个人内容放在`.learning/`或仓库外，不提交到公开仓库。

```text
这次想改善的体验或行为：
实际看到了什么问题：
相关旧概念和不确定的一点：
两个可能原因或两种方案：
这次只改变什么，必须保留什么：
预计现象，以及什么结果会推翻我的判断：
实际证据、成人/AI给过的提示、仍未验证的部分：
决定：保留 / 再试一项 / 回退 / 暂不深入。
下次用什么不同例子再检查：
```

当前本地工具仍按既有能力ID记录。超出已登记目标的探究先记简短自由笔记，不伪造新能力ID、不自动升级K、不声称调度器能评估任意新学科。
