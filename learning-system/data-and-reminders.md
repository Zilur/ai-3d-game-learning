# 本地记录、复习调度与通知边界

## 单一事实来源，不上数据库

所有个人资料默认放在已有忽略规则覆盖的`.learning/family/`。只有`state.md`中唯一的JSON代码块是机器数据源；外层Markdown方便说明用途，`TODAY.md`和会话输入都由它重新生成。

```text
.learning/family/
  state.md                  私人原始报告、配置、作废记录
  state.backup.md            最近一次写入前的备份
  TODAY.md                  派生的复习清单和四轴看板
  SESSION-A04.md            本课学生材料、教练协议、最小弱项摘要
  OPENMAIC-A04.md           教师生成规格；不含私人记录
  OPENMAIC-CONTEXT-A04.md   可选私人学情附件；成人预览确认后另行生成，不自动上传
  report-A04.json            待核对的暂存报告
  reminders.ics             日历提醒，不含知识弱项或孩子姓名
  cards/                    按需生成的47张逐课亲子卡
```

选择JSON代码块是为了避免解析自由格式Markdown表格造成误读；无需单独安装数据库或第三方包。孩子不需要读JSON。只有一个孩子也不要把个人日志直接填进公开课程模板。

程序不加密硬盘，不控制云备份；`.gitignore`也不是访问控制。电脑账户、备份和共享盘由成人管理。不要使用`git add -f .learning`；新工具没有上传、遥测或模型调用。

## 最小数据与来源

配置只存时区、陪伴模式、每日队列上限。不要求真实姓名、年龄、学校、家庭住址或生物信息。学习报告沿用现有评估格式，增加`family`：

```json
{
  "session_id": "2026-09-16-A04-01",
  "observed_on": "2026-09-16",
  "mode": "simulation",
  "novel_objectives": []
}
```

上例只是元数据示例，不是任何孩子的学习记录。报告中的`target_objectives`关联现有唯一能力ID；每项仍有四轴观察、提示级别、证据引用和诊断假设。观察必须写孩子实际回答或作出的判断，不用AI推测代替。

`novel_objectives`表示陪伴者核对本次迁移确实使用未讲过的新变式。工具只能检查声明与记录是否一致，不能知道孩子此前所有经历。`--confirm`同样只是成人核对声明，不是数字签名或对真实性的证明。

对话记录、截图和软件文件不复制进state，只留下必要的摘要与本地引用。首次使用不会创建假进度；模板分数全部为null。

## 写入、更正与恢复

保存前验证报告结构、日期、能力ID、提示级别、证据类型、模拟/软件边界和迁移新颖性声明。未加`--confirm`只检查、不写入。相同会话ID且内容相同不重复计数；同ID内容不同明确报错。

```sh
python3 tools/family_learning.py void 2026-09-16-A04-01 --reason "之前把观看演示误写成软件应用" --confirm
```

旧报告保留但不参与计算；修正版用新的session_id提交。派生状态每次从未作废的原报告重算，不另外维护一张容易漂移的分数表。同一天按导入次序处理，多天按观察日期处理；同日重复不能延长复习间隔。

使用独占写入锁、临时文件原子替换与最近一次备份，减少并发和中途写入损坏风险。异常退出留下锁时，先确认没有程序写入并备份，再移除`.write-lock`。不要自动删锁抢占。损坏JSON或未知schema会停止，不会悄悄重置。

恢复时先关闭写入程序并保留损坏文件，再由成人核对`state.backup.md`，复制恢复成`state.md`，执行`today`验证。删除个人资料时处理整个`.learning/family/`及自行创建的备份、上传副本和日历事件；工具不会自动追踪外部副本。

## 复习怎么计算

每一项M的四个维度独立计算。只有有分数且有证据的观察进入追踪；null保留为待验证，K不进入强制复习。

回忆和解释到期后进入每日清单，最多两项起步；实操和迁移弱项显示在“项目里再跟进”。到期排序优先避免遗忘旧项，同到期日优先已有错误，再看提示依赖。不是让孩子每天清空所有复习。

独立成功且到期、跨日才放大间隔；同日或提前重复不延长。错误或有提示的记忆观察回到下一日的小练习。跨周复测文字仅表示同维度存在相隔至少七天的独立成功记录，并不等于永久掌握或整个课程毕业。菜单与API查阅仍被允许；它们不应被误记成已泄露问题根因。

## 提醒的三层能力，不混为一谈

**第一层：清单已实现。** `today`在本地运行时重算到期项，session带上少量相关摘要。没有后台进程时，文件不会自己刷新。

**第二层：日历文件导出已实现。** `reminders`导出1–90天的事件，默认从次日开始。需要指定早晨时间，晚间可省略；采用配置时区按每日日期换算UTC。日历正文不包含个人知识点、姓名或原始记录。

**第三层：真正到时推送依赖外部日历。** 由成人导入ICS、检查所选日历的时区显示和通知权限，并实际测试一次。导出本身不会订阅通知，也没有自动写Google Calendar、发送邮件或建立聊天提醒。

日历只说“打开本地清单”，不会自动读取硬盘中的弱项。修改时间后需要重新导出并处理旧事件；不同日历对重复导入的处理可能不同，不承诺跨客户端自动去重。可单建一个“亲子小复习”日历，便于统一停用或删除。

不能保证关机、系统省电或权限关闭时收到通知；实际行为由日历与设备决定。本地工具没有常驻服务。需要操作系统定时刷新或云端同步时另行实现，不提前称已完成。

## 人格与能力隐私

只记录可修正的学习现象，如“本次混淆隐藏与阻挡”，不推断智力、心理状态、人格或成长诊断。AI生成的弱点必须有证据，并可由成人更正或作废。

孩子可以不录音、不录像、不公开作品；用成人简短观察也可取证。分享给外部AI前由成人查看SESSION内容，仅上传当前任务需要的材料，不批量发送全部个人历史。

## 与OpenMAIC运行记录的区别

OpenMAIC的作答/反馈/讨论记录不自动写进state.md；本地记录器也不是OpenMAIC内部的定时任务。`tools/openmaic_handoff.py`仅提供成人确认后的最小私人摘要，不改变记录、不宣称自动同步。完整边界与上游证据见[OpenMAIC能力核查](../openmaic/capability-audit.md)。
