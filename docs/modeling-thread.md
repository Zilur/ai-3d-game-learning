# 从具体玩法到运行模型：贯穿项目的刻意训练线

这是课程作者／AI教练的编排说明，不是孩子新增的必读课、打卡表或评分系统。具体课堂任务以`course/lessons/<ID>.md`为唯一正文；共同概念沿用[记忆清单](../course/memory.md)的KN与TH，不另设一套术语编号。教学方法与证据边界见[课程设计](design.md)。

## 这次补什么，不补什么

原课已有职责、状态、资源共享、预测和迁移任务；本轮补的是跨课连接、明确提炼的时机、不能照搬的对照，以及逐渐撤去提示。不是声称原课毫无基础，也不把局部知识存在当成完整架构能力已经培养。

目标是学习者逐渐从自己的玩法目标出发，理解必须记录哪些事实、哪些规则让它们变化、怎样观察并验证。这里的“底层”指可解释的系统关系，不等于先学习联机后端、内存优化或完整ECS。

八个锚点均已写入课内“这次多看一层”，不是只挂在成长指南里；它们复用原M、原题和实际材料。其余课按当前问题延伸，不把47课全部变成架构课。美术观察与创作仍保留自己的目标。

## 课程作者的连续安排

|课内入口|这次增加哪一层认识|与原任务怎样合并|以后怎样检验不是只会复述|
|---|---|---|---|

这不是按年龄固定执行的八次考试。初次不会可示范；某个关系已能主动使用就减少提示；陌生情境重新给帮助。跨课复现引用只是提醒关联，不凭课号推断孩子已掌握。

## 让经验变成可使用的模型

教师需要有意识地安排：先有小而正确的具体经验，再作有区分力的对照；到B08帮助明确提炼；随后把关系放回新目标中使用。不能只让孩子反复操作，等待自然悟出；也不能先发整张“正确结构图”，再把照图完成算自主设计。

每次只选择一处有意义的判断，替换重复讲解或本次候选题，不强制把预测、图示、反例、迁移和反思都做完。原对照已经提供证据就复用；一次简短口述或演示足够，不要求每课画图、交设计文档。

B08是明确点破的时机，B13和D07是撤去提示的机会。生成器会将教案、记忆和教师反馈都交给AI，但这些后台材料不能同时摊在初始学生页面上。第一次尝试后再按需解释；不能为了保住“独立”标签而一直拒绝帮助。

## 观察真实过程，而不是添一套表演界面

已有材料按问题复用，不新增必须先搭建的场景：

|要观察的关系|真实材料与边界|
|---|---|
|层级、整体与外观|[节点起点](../practice/godot/labs/scene_nodes/starter.tscn)；A03功能标记不是物理通过证明|
|输入、时间和位移|[运动Lab](../practice/godot/labs/motion_lab.tscn)；简化模型与实际控制器的边界仍按A05说明|
|请求、接受／拒绝、状态和重开|[事件Lab](../practice/godot/labs/event_lab.tscn)；按钮注入不是Area碰撞，实际拾取回到游戏|
|共享资源与独立运行状态|[材质Lab](../practice/godot/labs/material_lab.tscn)配[收集游戏](../practice/godot/scenes/main.tscn)；不以静态材质对照包办运行状态|
|条件、目标与交互结果|[交互Lab](../practice/godot/labs/interaction_lab.tscn)配[主游戏](../practice/godot/world/exploration.tscn)；未提供的宝箱／告示牌变式先标推演|

逐步从画面定位到同一个对象的真实状态，再到当前关键处理代码。先用已经存在的状态、日志、Remote或固定时长实验；没有单步控件就不声称有，不为教学仪式先造调试平台。

AI读取工程后才能指出具体文件和字段。读代码的最低目标是看懂当前条件、状态修改和一次调用顺序；API可查、实现可协助，但不能把因果理解一并外包。课堂模拟、原生实验、自己的修改版本是不同证据；一处通过不替代其余。

## 教孩子判断好坏，而不是背技术排名

先按明确目标判断是否正确：重复请求是否违反一次性约定、独立实例是否串改、重开是否恢复应恢复的状态。此类错误不以“架构取舍”掩盖。

两个方案都能正确表达当前规则时，再比较目标、改动范围、可解释性和验证成本。共享还是独立、何时发生结果、某种限制要不要保留，要依据当前目标；不是组件越多、代码越长、采用ECS就越专业。

成熟工具和约定不必重新发明；需要知道调用边界、关键状态的责任和如何发现错误。不能把“AI通常知道做法”升级成“AI一定正确，所以不必验”。高风险和超出能力的工程审核仍交给有能力的人，不让儿童独自承担。

## 检查是否开始形成认知，而不只检查做出成品

在原任务中分散观察三种行为：是否能主动提出影响规则的条件；是否能在运行前给出可核对预测；结果不符或目标变化时，是否能说明该保留和调整哪里。不是每课三份作业，也不把它们压成一个智力或架构总分。

先给目标、已学范围和必要材料，不先给字段名称与处理顺序。允许有多种合理玩法选择，不设隐藏的唯一设计答案。缺少证据时写尚未观察；给过根因或方案后如实说明帮助，再择机换一个未预演条件。

初学时答不出不等于能力差，术语不熟也不等于关系不懂。软件入口可提示；如果概念本身不清楚，明确讲一个小例子。爸爸仍是分享对象而非关卡批准人，不要求评分、签字或在场。

## 如何继续到建筑、英雄、塔、敌人与地形

沿用[成长指南](../course/growth.md)的小作品—原型—受控生产路线。以下是后续可选择的任务，不宣称现在已经配齐对应玩法工程，也不成为D07的前置。

先做一个有目标的薄片，再让真实变化挑战原模型。例如，先做一种可攻击对象，下一次增加一个不同阵营或可治疗对象，检查哪些规则可复用；先做固定建造位，确实要自由摆放时再研究占地和通路；先做一个有持续时间的效果，再讨论另一个效果到来时的关系。

每次只深化一个选择。需要记住剩余时间时才深入计时状态；需要很多单位查询时才深入相应数据结构与算法；实测发现相关瓶颈时才比较局部批处理或ECS。数据配置、状态模型、执行规则与存储优化不是同一个课题，不把完整ECS当通用终点。

后续仍保留“从目标提出规则—观察运行—比较方案—局部实施—换条件验证”的工作方式。停止扩大规模或采用简单实现也可以是有依据的决定；不以商业销量或框架复杂度评价孩子。
